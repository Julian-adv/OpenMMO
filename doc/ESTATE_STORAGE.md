# Estate Storage: 영지 보관함

`Wooden Storage Chest`는 `furniture` 아이템을 소비해 소유 중인 활성 영지에 배치한다. 건물
안에서는 캐릭터가 서 있는 층에만 배치되며, 배치 격자와 보관함 렌더링도 현재
층으로 제한한다. 현재 구현된 보관 한도는 50kg 한 단계이며 영지당 설치 개수는
제한하지 않는다.

그리다의 ORKEA 상점에서 1,200동화(은화 12개)에 구매한다. 전시 상자를 클릭하거나
그리다의 `Buy` 목록에서 고를 수 있다. 알드윈의 판매 목록에는 포함하지 않는다.

보관함 종류별 모델·용량·스냅·회전·풋프린트·층 범위·경계 여유·충돌 반경은
`data-src/estate_storage.csv`에서 관리한다. `data/estate_storage.json`은 빌드 시
자동 생성하며 Git에 저장하지 않는다. 설치 DB는 `item_def_id`를 저장하므로
배치, 렌더링, 용량 계산과 회수 모두 같은 정의를 사용한다.

[ORKEA 전시 판매](FURNITURE_SHOP.md)의 장식품도 같은 배치·회수 경로를 사용한다.
`capacityKg=0`인 항목은 보관 UI를 열 수 없으며, `maxHeightOffset`은 테이블 위 등
높이를 조절할 수 있는 소품의 배치 범위, `textLabel`은 간판 문구 편집 여부다.

설치한 Bed·Rustic Bed는 왼쪽 클릭하면 가까이 다가가 눕고, Chair는 앉는다.
침대에서 연속 16초 동안 쉬면 HP·MP 자연 회복량이 각각 2배가 된다. 전투·허기 등
각 자원의 기존 회복 제한은 유지하며, 일어나거나 이동·공격·시전·아이템 사용·피격으로
수면이 끝나면 보너스도 종료된다.
배치된 방향과 모델별 높이를 사용하며 이동하면 일어난다. 같은 가구는 한 명만
사용할 수 있고, 사용 중에는 회수할 수 없다. 상호작용의 `object_type`은 아이템
정의 ID를 사용해 맵 에디터 오브젝트와 설치 가구의 ID가 겹쳐도 구분한다.

인벤토리에서 사용하는 아이템의 기능 진입은 표시 이름이나 특정 ID 문자열이 아니라
`items.csv`의 `useAction=estate_storage`로 결정한다. 보관함 아이템을 직접 사용하거나
`Estate Editor`의 `Objects` 탭에서 선택하면 같은 배치 인터페이스가 열린다. 펜스도
같은 탭에서 선택하지만, 위치 판정은 각각 셀 변과 면적형 가구 전략으로 분리한다.

보관 UI는 거래창의 양쪽 목록 레이아웃과 인벤토리 무게 막대를 재사용한다. 왼쪽은
보관함, 오른쪽은 플레이어 가방이며 선택 결과의 최종 무게와 남은 무게를 각각
표시한다. 귀속·거래 불가 아이템과 보관함 자체는 넣을 수 없다.

빈 보관함은 회수할 수 있다. 회수한 보관함 무게를 가방이 감당하면 아이템으로
돌려주고, 무게를 초과하면 기존 위치의 드롭 아이템으로 바꾼다. 마을 회수함은
구현 범위에 포함하지 않는다. 영지가 해제된 뒤 보관함은 현장에 남고 누구나 열어
내용물을 가져갈 수 있다.

`Estate Editor → Objects`의 `Select`를 누른 뒤 현재 층의 가구를 왼쪽 클릭하면
이동·회전 편집을 시작한다. 편집에는 거리 제한이 없으며, 보관함 열기는 3m 이내에서만
가능하다. 마지막 저장 위치는 반투명하게, 커서를 따라가는 미리보기는 정상 표시한다.
왼쪽 클릭이나 `Enter`로 위치·방향·높이를 저장하며 편집을 계속한다. 서버는 저장할 때
위치·소유권·충돌·수정 버전을 검증한다. `Done`이나 `Esc`는 마지막 저장 위치를 유지하고
편집을 끝낸다. 이동은 가구 ID, 보관함 내용물, 간판 문구를 유지하며 인벤토리를 거치지
않는다. `Recover`로 회수할 수 있으며, 사용 중인 침대·의자는 이동하거나 회수할 수 없다.

가구 목록에는 가방에 있는 가구만 표시하며 약 7개 행까지 펼치고 나머지는 스크롤한다.
선택·편집 중에는 목록을 숨기며 `Done`으로 돌아간다. 간판을 선택하면 회전 설정 위의
`Sign text` 입력란과 `Save text` 버튼으로 문구를 편집할 수 있다.

보관함이 놓인 건물은 철거할 수 없다. 모든 층의 보관함을 먼저 비우고 회수해야 한다.

## 배치 규칙

- 클라이언트 미리보기와 서버가 같은 가구 풋프린트, 회전 및 층 판정을 사용한다.
- 가구 전체와 외벽 여유 공간이 현재 층의 바닥 안에 들어와야 한다.
- 회전 버튼과 `R`/`Shift + R`로 모델별 각도 단위로 회전한다. 침대·의자·테이블·벽 횃불·샵 사인은 90도 단위다.
- 화살표 키로 남북·동서 방향을 5cm씩 미세 조정한다. 모든 가구의 배치 격자는 5cm다.
- 마우스 휠이나 높이 슬라이더로 장식품의 바닥 기준 높이를 조절한다. `Ctrl + 휠`은 카메라 줌이다.
- 직접 회전하기 전에는 경계 안에 들어가는 방향을 자동으로 찾는다. 직접 선택한 방향은 유지하며, 경계를 침범하면 빨간 미리보기로 표시하고 설치를 막는다.
- 두 방향 모두 경계나 계단 공간을 침범하면 설치할 수 없다.
- 같은 층에 배치된 다른 보관함의 실제 회전 풋프린트와 겹치면 설치할 수 없다.
- 커서 위치와 실제 설치 위치가 달라지지 않도록 서버가 임의로 안쪽으로 이동시키지 않는다.

## 논의가 필요한 사항

- 바닥형 가구와 외벽 사이의 최소 여유 공간을 현재처럼 0.1m로 강제할지, 모델별
  여유 공간을 둘지 결정해야 한다. 어떤 경우에도 가구 모델 또는 충돌 영역이 건물
  밖으로 튀어나오는 배치는 허용하지 않는다.
- 추후 벽에 붙이는 가구가 필요하면 바닥형 가구의 예외로 처리하지 않고, 벽을
  기준으로 스냅하는 별도의 `wall-mounted` 배치 유형을 도입할지 논의한다.
- 75kg·100kg·200kg 등 상위 보관함을 추가할 때 기존 내용물을 유지하는 제자리
  업그레이드를 제공할지 추후 논의한다.
- 영지당 보관함 개수 제한은 현재 두지 않는다. 경제·서버 부하·공간 악용 문제가
  확인될 경우에만 설치 개수나 영지별 총 보관 무게 제한을 다시 검토한다.
