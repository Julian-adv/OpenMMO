# ORKEA 전시 판매

마을 `world(-1450.5, 1.0, 4775.5)` 부근에 배치한 매장을 사용한다. 전시품을 가까이서
클릭하면 별도 카트의 미결제 목록에 한 개씩 추가된다. 그리다를 클릭하면 기존 상점 창이
열리고 가운데 구매 목록에 고른 가구가 표시된다. `Confirm`으로 결제하면 가구·장식품
아이템을 지급한다. 미결제 목록은 실제 아이템이 아니며
매장 밖으로 나가거나 접속을 종료하면 비워진다.

현재 전시물 25개, 판매 품목 23종이다. 침대·의자·테이블·상자·통·벽난로·횃불·간판과
물약·두루마리·검 소품을 포함한다. 외부 `ORKEA` 간판(ID 84)은 판매하지 않는다.
전시물은 클릭해도 현장에 남고, 재고 수량은 제한하지 않는다.

오크 여성 점원 **Grida (그리다)**가 서쪽 계산 구역 옆
`world(-1452.0, 1.0, 4777.0)`에서 06:30–18:00, 18:30–자정에 손님을 안내한다.
00:00–06:00에는 매장 안 85번 침대에서 자고, 06:00–06:30과 18:00–18:30에는
여관 1층 46번 의자에서 각각 아침과 저녁을 먹는다. 점원과의 대화는 전시품 선택과
그리다의 상점에서 결제하는 방법을 설명한다. 출입구 접근만으로 결제창을 열지는 않는다.
NPC 실행 설정에는 `[[npcs]] id = "grida"`, `account = "npc_grida"`,
`gender = "female"`을 추가한다(`agent-client/data/config.toml.example` 참조).

## 구매와 배치

- 전시물 3m 이내에서 클릭해 담는다. 한 번에 최대 64개까지 결제할 수 있다.
- 전시 보관함이나 침대를 담으면 매장에 있는 그리다에게 선택 이벤트를 전달해 짧은 사용 팁을
  말하게 한다. 보관함은 자기 영지에 설치해야 사용 가능하며 50kg까지 보관할 수 있다고,
  침대는 16초 연속 수면 후 HP·MP 자연 회복량이 2배가 된다고 설명한다.
  같은 손님에게 같은 종류의 팁은 5분에 한 번만 전달하며 두 침대는 같은 종류로 취급한다.
  그리다가 자거나 매장에 없을 때, 담기에 실패했을 때는 안내하지 않는다.
- 별도 카트에서 수량과 합계를 확인하고 품목을 뺄 수 있다.
  카트는 인벤토리를 열어도 계속 표시하며, 인벤토리 안에는 중복 표시하지 않는다.
- 그리다를 클릭하면 기존 상점 창 가운데 카트에 선택한 품목과 수량이 채워진다.
  왼쪽 판매 목록에는 전시 판매 품목 23종을 모두 표시하며, 목록에서 클릭해도 한 개씩 담긴다.
  전시물을 둘러보지 않고 메뉴에서 바로 골라 구매할 수 있고, 전시물에서 담은 수량과 합산한다.
  같은 종류는 합쳐 표시하고, 카트의 품목을 클릭하면 한 개씩 뺀다. 창을 닫아도 선택은 유지한다.
- `Confirm`을 누르면 그리다와의 거리·수면 상태, 소지금, 휴대 중량을 확인해 전체 주문을
  한 번에 저장한다. 결제 실패 시 목록을 유지하며, 잔액·가격이 바뀌었거나 전시물이 제거되면
  결제를 거절한다. 가구 판매 가격은 고정이다.
- 그리다는 리카와 동일하게 가격이 있는 사용자 물건을 기본가의 40%에 매입한다.
  잠긴 물건은 제외하며, 시장 가격에 따른 매입 상한과 최근 판매품 되사기도 기존 상점 규칙을 따른다.
  `Sell (40%)`에서 고른 물건은 가구와 같은 카트에 표시하고, `Confirm` 시 판매부터 처리해
  그 대금으로 가구를 살 수 있다. 판매와 가구 구매는 각각 처리되므로 가구 구매가 실패해도
  앞서 완료된 판매는 유지된다.
- 아이템을 사용하거나 `Estate Editor → Objects`에서 선택해 자기 활성 영지에 배치한다.
- 왼쪽 클릭이나 `Enter`로 배치하고 회전 버튼, `R`/`Shift + R`로 회전한다. 침대 등 큰 가구와
  벽 횃불·샵 사인은 90도 단위이며, 직접 선택한 방향은 경계에서도 유지한다. 화살표 키는
  남북·동서로 5cm씩 이동한다. 작은 장식품은 테이블 표면에 올릴 수 있으며, 휠이나 높이
  슬라이더로 바닥 기준 최대 3m까지 조절한다. `Ctrl + 휠`은 카메라 줌이다.
- `Objects → Select`를 누르고 현재 층의 가구를 왼쪽 클릭하면 거리 제한 없이 이동·회전할 수 있다.
  선택한 가구의 현재 배치 위치에는 파란색 선택 상자를 표시한다. 마우스를 따라가는
  미리보기에는 표시하지 않으며, 이동을 저장하면 새 배치 위치로 갱신된다.
  왼쪽 클릭이나 `Enter`로 저장해도 편집을 유지하며 `Done`이나 `Esc`로 종료한다.
  내용물과 간판 문구는 이동 후에도 유지된다. `Recover`는 아이템으로 회수하며, 가방 중량이
  부족하면 현장에 드롭된다. 간판 문구는 선택 후 `Sign text`에서 편집하고 `Save text`로 저장한다(최대 120자).
- 전시 상자 94번과 그리다의 판매 목록에서는 `Wooden Storage Chest`를 1,200동화(은화 12개)에
  판매한다. 영지에 설치하면 50kg까지 보관할 수 있으며, 알드윈은 더 이상 보관함을 판매하지 않는다.
- 장식 물약·두루마리는 소비 효과가 없고, 장식 검은 장착할 수 없다. 이전에 구매한
  장식 상자 `furniture_chest`는 그대로 유지되며 보관함 기능은 없다.
- 회수한 간판의 문구는 아이템에 보존되지 않으므로 다시 배치한 뒤 편집한다.

## 운영 데이터

`data/furniture_shop.json`은 매장 영역, 점원 이름, 판매 대상 전시물 ID와 가격(동화 단위)을
정의한다. 가격은 초기 설정값이며 운영 시 조정할 수 있다. 물약·두루마리·검은 개당
200동화, 의자는 800동화, 테이블은 3,000동화 등이다.

품목 정의는 `data-src/items.csv`, 배치 정의는 `data-src/estate_storage.csv`에 있다.
`node tools/convert.mjs`로 JSON을 갱신한다. 기존 보관함 배치·회수·충돌·영지 권한
경로를 재사용하며, `capacityKg=0`인 항목은 장식품이다. 간판 문구는
`estate_chests.text`에 저장한다. 스키마는 서버 시작 시 자동으로 갱신된다.

매장 건물과 전시물은 코드와 별도로 저장되는 운영 데이터다. 다른 환경에 반영할 때
다음 데이터를 함께 옮기고, 실제 전시물 ID가 판매 설정과 일치하는지 확인한다.

- 건물: `data/housing/r-23_+74/r-23_+74_5.json`
- 전시물: `data/terrain/objects/r-02_+04.json`의 해당 매장 배치
- 판매 대상 ID: 85–90, 92–110 (현재 배치 기준)
- 전시 상자 ID 94의 `type`은 `chest_animated`다. 이전 `chest` 전시물은 위치·회전·ID를
  유지한 채 모델만 교체하고, 판매 설정도 `storage_chest`로 함께 갱신한다.

건물 파일을 직접 옮기면 건축 시 지형 정리가 실행되지 않는다. 운영 원본을 백업한 뒤
지상층 지형을 건물 `origin.y`에 맞추고, 바깥 4m는 완만하게 연결한다. 이웃 건물의
기초 영역과 타일 경계의 높이를 보존한다. 지상층 방 주변의 풀은 1m, 나무는 2m까지
제거한다. 개발 지형을 통째로 복사하지 않고 운영 타일의 해당 영역만 수정한다.

현재 매장은 `r-02_+04`의 높이 타일 `h_-0023_+0075.bin`·`h_-0022_+0075.bin`,
풀 타일 `g_-0023_+0075.bin`, 나무 타일 `t_-0023_+0075.bin`이 정리 대상이다.
높이·풀 저장 API로 서버 높이 캐시와 지형 해시, 접속 중인 클라이언트를 갱신한다.
나무 파일을 직접 수정했다면 같은 타일의 해시도 다시 게시해야 한다. 공개 파일에서
지형이 바닥 윗면 아래인지, 제거 영역에 풀·나무가 없는지 확인한다.

앞 광장의 돌바닥은 같은 타일의 조경 파일 `l_-0023_+0075.bin`에 있다.
바닥 재질과 식생 제거 마스크는 별도이므로, 돌바닥을 옮길 때는 돌(slot 7)이 우세한
셀의 제거 표시도 확인한다. 재질만 적용하면 기존 풀이 남을 수 있다.

서버는 결제 시 저장된 전시물의 ID·종류·위치·층을 다시 확인한다. 맵 에디터에서
전시물을 새로 만들거나 교체하면 판매 설정의 `displayIds`도 갱신해야 한다.
클라이언트·서버·NPC 에이전트는 프로토콜 89 및 동일한 판매 설정으로 함께 빌드해야 한다.
