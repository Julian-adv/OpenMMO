# 캐릭터 커스터마이제이션과 장비 외형

작성일: 2026-09-28. 갱신: 2026-10-05. 상태: 남성 얼굴·헤어 선택과 저장, 방어구 슬롯별 외형 연결 완료.

2026-10-05 캐릭터 생성창에 남성 6개 직업의 얼굴·헤어 선택 메뉴를 추가했다.
얼굴은 기본·각진 얼굴, 헤어는 크롭·웨이브 장발과 뼈 장식·머리 없음 중 선택한다.
생성 미리보기에서는 투구를 벗겨 외형을 확인한다. 게임에서는 장착한 투구가 헤어를 숨기고,
투구를 벗으면 저장한 헤어가 다시 표시된다. 각진 얼굴의 두상을 표준에 맞춰 크롭·웨이브 헤어를 기본 얼굴과 공유한다.
선택값은 `characters.appearance` JSON에 저장하며, 기존 캐릭터에는 기본 얼굴·크롭을 적용한다.
선택 화면·본인·다른 플레이어·감정표현 미리보기에 같은 선택값을 전달한다.
프로토콜은 115이며 서버·웹 WASM·에이전트를 함께 재빌드해야 한다.
게임용 에셋과 재생성 방법은 [얼굴·헤어 제작 기록](assets/modular-rugged-face-wavy-hair.md)을 따른다.

2026-09-29 사용자 요청에 따라 기존 캐릭터를 포함한 남성 플레이어 6개 직업
(기사·바바리안·로그·원시인·레인저·사제)의 표시 모델을 첫 모듈형 남성으로 통일했다.
기사의 기본 외형은 판금 갑옷·바지·신발·장갑·열린 헬멧이며, 나머지 남성 직업은
갈색 크롭 헤어·천 셔츠·천 바지·가죽 부츠다. 생성·선택 화면, 본인·다른
플레이어와 감정표현 미리보기가 같은 조립 경로를 사용한다. 여성과 공식 NPC의 모델은 유지한다.
당시에는 외형만 바꾸고 DB의 캐릭터·아이템 데이터는 수정하지 않았다. 방어구 장착에 따른 의상 변경과
얼굴·헤어 저장은 이후 연결했다. 머리색·눈색 저장은 후속 단계다. 아래의 기존 캐릭터 유지·선택적 전환 설계보다 이번
사용자 요청의 남성 기본 외형 일괄 적용을 우선한다.

정리하고 최종 파츠 GLB 8개, 편집용 Blender 파일, 확정 애니메이션·검 그립 설정을 남겼다.
실제 프롬프트·생성 설정·작업 ID·비용·라이선스는 [출처 기록](assets/modular-human-male-01-sources.json)에 보존한다.

첫 체형은 성인 남성 표준 체형이며, 손바닥이 아래·몸통 쪽을 향하는 Mixamo 65본 리그를 쓴다.
최종 몸체는 13,520 triangles, 얼굴 지정 영역은 1,505 triangles다.
손가락·검 그립·걷기·점프 접지와 전투 대기 어깨, 일반 대기 팔 간격 보정을 전용 동작에 저장했다.
미리보기와 게임은 이 확정 동작을 직접 재생하며 중복 리타게팅·접지·손가락 보정을 적용하지 않는다.

개발 미리보기에서는 헤어 2종·상의 3종·하의 2종, 가죽·판금 장갑과 신발,
판금 헬멧 착탈과 머리색·눈색을 바꿀 수 있다.
가죽 갑옷은 안쪽 셔츠의 몸통 중앙을 숨기고 겨드랑이·소매·갑옷용 목깃을 표시한다.
판금 상의는 자체 소매·목깃을 사용하며 셔츠와 겹치지 않는다.
몸체 가림과 부츠용 바지 끝단 변형도 함께 갱신한다. 천 셔츠는 허리밴드 안으로 넣었으며,
소매·팔꿈치 가중치, 허리·목 가림 경계, 갑옷 뒤어깨와 목깃 보정을 반영했다.
머리 재질은 복제하고 홍채에는 이 체형 전용 마스크를 사용한다.

장갑·부츠·검을 포함한 제작용 조합은 천 셔츠 **24,408–24,586**(표시 **12,862–13,040**),
가죽 갑옷 **28,165–28,343**(표시 **15,009–15,187**) triangles다.
숨긴 몸체·안쪽 의상·목깃·바지 끝단 변형을 포함하며 망토는 별도다.
실제 게임의 장갑 없는 기본 복장과 철검은 숨김 포함 **23,375**, 표시 **14,232 triangles**다.
옷·장갑의 관통과 헤어 표면, 15,000–20,000 triangles 목표를 넘는 조합 예산의 검토가 남아 있어
**1단계는 아직 완료로 판정하지 않는다**. 파일 정리는 현재 결과물의 보관 범위를 정한 것이다.

캐릭터를 공통 뼈대에 연결된 여러 파츠로 구성한다. 플레이어는 헤어 스타일과
머리색·눈색을 선택하고, 장착한 상의·장갑·하의·신발에 따라 캐릭터의 외형이
바뀐다. 생성 화면, 캐릭터 선택 화면, 본인과 다른 플레이어의 게임 화면에서
같은 외모와 장비를 표시한다.

제작 흐름은 **Codex ImageGen 원화 → Meshy 형상 생성 → Blender 파츠 정리와
공통 리깅 → 기존 Mixamo 애니메이션 재사용**을 기본으로 한다. Meshy 리깅과
애니메이션은 샘플로 비교한 뒤 채택 여부를 판단한다.

## 2. 기본 결정과 첫 범위

- 몸체와 교체용 스킨 파츠는 캐릭터별 기준 뼈대 하나를 공유한다. 파츠별 애니메이션이나
  장비별 자동 리깅을 만들지 않는다. 기존 절차적 망토의 보조 뼈대와 시뮬레이션은 유지한다.
- 외모는 캐릭터에 저장하고, 장착 외형은 서버가 확정한 장비에서 결정한다.
  외모 선택으로 능력치·장비 성능·충돌 크기를 바꾸지 않는다.
- 첫 구현은 고정 체형 하나, 얼굴 하나, 짧은 헤어 2종, 머리색·눈색 선택,
  교체용 상의 2종, 장갑·바지·부츠 한 세트를 대상으로 한다.
- 장비를 벗었을 때 사용할 기본 복장도 제작한다. 기본 복장은 시각적 기본값이며
  인벤토리 아이템이나 능력치를 제공하지 않는다.
- 기존 Mixamo 동작과 무기·망토 기능을 재사용한다. 외모가 없는 캐릭터와 NPC는
  기존 모델을 사용하며 단계적으로 전환한다.

체형 슬라이더, 얼굴 조형, 긴 머리 물리, 긴 치마·로브·망토의 통합 의상 시스템,
전 장비의 개별 모델 제작, 장비 형상변환과 방어구 염색은 후속 범위다.
생성 후 미용 서비스의 비용·아이템·NPC도 이 문서에서 정하지 않는다.

## 3. 파츠와 겹침 규칙

| 파츠 | 연결 방식 | 선택 또는 교체 규칙 |
| --- | --- | --- |
| 몸체·얼굴 | 기준 스켈레톤에 스킨 | 첫 버전은 고정 체형·얼굴. 가려진 신체 영역만 숨김 |
| 머리카락 | 짧은 머리는 `Head` 연결 또는 동일 리그 스킨 | `hair_style`로 교체, `hair_color`로 색 변경 |
| 눈 | 얼굴의 홍채 마스크 또는 별도 눈 재질 | `eye_color`는 홍채에만 적용. 색 변경만으로 별도 메시를 강제하지 않음 |
| 상의 | `shirt`·`chest`에 대응하는 스킨 파츠 | 셔츠와 갑옷의 겹침 규칙으로 표시 결정 |
| 장갑 | 손·손가락에 스킨 | `hands` 아이템에 따라 교체, 필요한 손 영역 숨김 |
| 하의 | 골반·다리에 스킨 | `pants` 아이템에 따라 교체. 첫 버전은 바지 |
| 신발·부츠 | 발·발가락에 스킨 | `boots` 아이템에 따라 교체, 부츠 안의 하의 영역 숨김 |
| 투구 | `Head` 연결 또는 스킨 | `head` 확장 경로 확보. 첫 세트의 필수 제작 대상은 아님 |

몸체는 목·몸통·상완·전완·손·골반·허벅지·종아리·발 등 가릴 수 있는 영역을
구분한다. 파츠는 영역별 `hide_body_regions`와 다른 파츠를 가리는 영역 정보를
가진다. 먼저 로드에 성공한 장비와 기본 복장을 결정하고, 겉옷이 안쪽 파츠를 가리는
규칙을 적용한다. 그 후 실제 표시되는 파츠 영역이 가리는 신체 영역을 합집합으로
계산한다. 장비를 벗거나 기본 복장으로 대체할 때도 처음부터 다시 계산한다.

갑옷은 가려지는 셔츠 영역을, 긴 부츠는 바지의 종아리 영역을 숨긴다. 짧은 장갑과
긴 장갑도 서로 다른 영역을 가릴 수 있다. 몸통 전체를 숨기는 식의 거친 규칙으로
민소매의 팔이나 갑옷의 목 주변까지 사라지지 않도록 에셋별로 지정한다.
초기에는 영역별 메시 가시성으로 구현하고, 드로우콜 측정 후 필요한 부분을 합친다.
가림 관계는 갑옷→셔츠, 장갑→소매, 부츠→바지처럼 대상 파츠·영역을 명시한다.
서로를 가리는 순환 관계와 존재하지 않는 영역 참조는 카탈로그 검증에서 거부한다.

투구는 헤어 표시 정책을 `keep`, `hide`, `variant`로 갖는다. 헤어를 숨겨도
저장된 스타일과 색은 유지한다. `variant`는 헤어별 투구용 변형을 지정하고,
해당 변형이 없으면 `hide`로 표시한다. 긴 치마나 로브처럼 상·하의를 함께 덮는 의상은
후속 단계에서 한 외형이 여러 표시 영역을 점유하도록 확장한다.

빈 슬롯과 미지원·로딩 실패 외형에는 다음 기본값을 적용한다. 기본 복장도 같은
가림 규칙을 따르며, 없는 장비의 가림 정보는 적용하지 않는다.

| 슬롯 | 기본 표시 |
| --- | --- |
| `shirt` | 기본 상의. 갑옷이 덮는 영역은 숨김 |
| `chest` | 갑옷 없음. 착용 셔츠 또는 기본 상의 사용 |
| `pants` | 기본 하의 |
| `boots` | 기준 접지 높이에 맞춘 기본 신발 |
| `hands`·`head` | 장갑·투구 없음. 손과 선택한 헤어 표시 |

아이템의 성능·장착 상태는 그대로 유지한다. 지원하지 않는 체형에 다른 체형의
장비 메시를 강제로 늘려 입히지 않는다.

## 4. 공통 리그와 에셋 규격

### 체형별 기준

첫 몸체를 기준으로 `rig_id`와 `body_type`을 정한다. 이름만 같은 본을 가진
모델은 호환 파츠로 취급하지 않는다. 다음 항목을 일치시켜야 한다.

- 본 이름·부모 계층·기준 자세의 위치와 회전
- 원점·단위·전방 방향과 메시의 기준 변환
- 스킨의 조인트 매핑, bind matrix와 inverse bind matrix
- 목·손목·허리·발목의 접합 위치와 겹침 여유. 피부를 분할한 경계는 위치·노멀·가중치 유지

런타임은 미터 단위, Y 위쪽, +Z 전방, 발밑 원점을 기준으로 한다. 손가락이 있는
Mixamo 계열 리그를 목표로 하고, 최초 몸체 검증 후 본 목록과 기준 자세를 고정한다.
Blender 작업 좌표에서 GLB 좌표로 변환하는 절차도 기준 파일에 포함한다.

새 체형은 별도 `body_type`으로 등록하고 의상별 맞춤 변형을 제작한다. 서로 다른
체형이 애니메이션을 공유하더라도 장비 형상까지 자동 호환된다고 가정하지 않는다.
뼈대의 기준 자세를 바꾸는 수정은 새 `rig_id`로 배포한다.

### 파일과 재질

예상 배포 위치는 `client/public/models/characters/modular/<body_type>/` 아래의
`base.glb`, `hair/`, `tops/`, `hands/`, `bottoms/`, `boots/`다. 실제 ID와 파일명은
첫 샘플 제작 시 고정한다. `base.glb`에는 의상 없이도 완전한 몸체·두피·기준 리그를
보존하고, 기본 복장은 독립 파츠로 둔다. 몸체를 가리는 처리는 런타임 가시성으로
수행하며 원본 피부를 삭제하지 않는다. 몸체·파츠 GLB에 공용 애니메이션을 중복 저장하지 않는다.

독립 파츠 GLB에는 검증과 바인딩을 위한 기준 리그를 포함할 수 있다. 로드할 때
조인트 인덱스를 기준 뼈대에 맞추고 bind 정보를 확인한 뒤 캐릭터 뼈대에 연결한다.
원점·크기 보정은 제작 단계에서 완료한다. 조인트 재매핑이 필요하면 공유 원본
지오메트리를 직접 수정하지 않고 해당 리그용 변환 결과를 캐시한다. 연결 후 파츠의
뼈대 사본은 씬에서 제거해 같은 본 이름에 애니메이션이 중복 바인딩되지 않게 한다.
정적 부착물은 검증된 본과 로컬 부착 변환을 사용한다.

머리카락은 색을 바꿔도 명암이 유지되는 중립색 텍스처를 사용한다. 눈은 흰자와
동공을 보존하고 홍채만 바꾼다. 채색된 텍스처 전체에 색을 곱해 피부나 흰자까지
변색시키는 방식은 사용하지 않는다. 색 변경은 메시·리그 재생성 없이 처리한다.

### 폴리곤과 얼굴 품질

모듈형 캐릭터는 **모든 파츠를 합쳐 약 15,000~20,000폴리곤**을 목표로 한다
(사용자 확인: 2026-09-28). 동시에 사용하는 몸체·얼굴·눈·헤어·의상·장비 파츠
전체에 예산을 배분하며, 부착된 무기와 절차적 망토도 합산한다. 계산 단위는 한
캐릭터의 한 장착 조합이다. 조립된 파츠 GLB와 절차적 지오메트리의 삼각형 수를
합산하고, 가려진 영역도 포함한 총량과 실제 표시량을 구분해 기록한다. 생성 도구의
면 수는 별도로 남기며, 렌더 패스별 중복 그리기 비용은 드로우콜·프레임 시간으로 측정한다.

**얼굴에 더 많은 폴리곤을 우선 배분한다.** 눈꺼풀·눈 주변, 코, 입술과 턱선의
형태를 살리고, 얼굴 확대 미리보기에서도 윤곽이 각져 보이지 않도록 제작한다.
가려지는 몸체나 넓고 평평한 의상 면은 필요한 밀도로 유지한다. 얼굴의 부위별
배분은 샘플을 보고 조정하며, 단순히 전체 메시를 세분화해 수만 늘리지 않는다.
얼굴과 홍채의 UV 면적·텍스처 해상도도 함께 확보한다. 텍스처 압축·축소 후의
최종 GLB로 확대 미리보기를 확인하고, 부위별 해상도와 압축 품질은 그 결과로 정한다.

[에셋 제작 지침](assets/creation-guidelines.md)에도 이 합산 목표를 적용한다.
파츠별 생성 목표는 전체 예산에 맞춰 정하고, 일반 아이템의 약 4,000폴리곤 목표를
각 착용 파츠에 일괄 적용하지 않는다. 조립 모델의 재질·텍스처 비용과 성능도 함께
측정한다. 폴리곤 수는 대략적인 목표이며 숫자만 맞추기 위한 일괄 감면은 하지 않는다.

## 5. 제작 파이프라인

1. **원화 제작 — Codex ImageGen.** 같은 체형·얼굴·비율을 유지하는 정면·측면·후면
   기준 이미지와 장비별 이미지를 만든다. 빈손의 중립 A포즈를 사용하고 머리카락,
   손가락, 옷의 경계가 식별되도록 한다. 손바닥은 아래·몸통 쪽을 향하게 하고,
   손가락은 측면에서도 확인한다. 정면에 손바닥을 보이려고 전완을 비틀지 않는다.
   각 시점의 원화가 서로 일치하는지 검토한다.
2. **기본 형상 — Meshy.** 기준 몸체와 장비 형상을 생성한다. 몸체는 단순한 기본
   복장으로 시작하고, Blender에서 몸체·두피·기본 복장을 분리·보완한다. 얼굴과
   관절의 면 배치, UV를 정리한 후 기준 리깅으로 넘어간다. 독립 생성 파츠가 바로
   맞거나 생성 도구의 폴리곤 목표만으로 얼굴 밀도가 확보될 것을 전제하지 않는다.
3. **기준 리그 — Mixamo와 Blender.** 정리한 몸체를 한 번 리깅하고, 기존 애니메이션과
   손가락·무기 자세를 확인한다. 이후 장비는 이 기준 리그에 가중치를 전달하고
   관절 주변을 보정한다. 리깅 후 면 배치를 바꾸면 가중치도 다시 검증한다.
   Mixamo 업로드 패키지는 기존 에셋 제작 지침을 따른다.
4. **파츠 정리 — Blender.** 체형 맞춤, 경계 보완, UV·재질 분리, 가림 영역 지정,
   가중치 보정과 GLB 내보내기를 수행한다. 자동 가중치 전달 결과도 동작으로 검증한다.
5. **게임 검증.** 같은 파츠를 생성 미리보기와 실제 클라이언트에서 조립해 기존 동작,
   장착 교체, 원격 플레이어 표시를 확인한다.

기존 모델은 분리 가능한 헤어·의상·얼굴을 재활용할 수 있다. 옷 아래 몸체의 존재나
분리 후 경계 품질은 GLB의 메시 개수만으로 알 수 없으므로 실제 형상을 검사한다.
현재 [캐릭터 내보내기 스크립트](../tools/blender-scripts/export_character.py)는
메시 하나를 선택해 재질을 이식한다. 모듈형 내보내기는 여러 메시·재질·가림 영역과
공통 리그를 보존하도록 별도 경로를 만들고, 기존 단일 모델 경로는 유지한다.

Meshy Auto Split은 공식 API 기준 프린팅용 분할이며 입력 텍스처를 보존하지 않는다.
게임용 리깅·UV·교체 경계를 만드는 단계로 채택하지 않는다.
[Meshy Auto Split API](https://docs.meshy.ai/en/api/auto-split), 2026-09-28 확인.

### Meshy 리깅·애니메이션 비교

기본안은 기존 Mixamo 팩 재사용이다. Meshy는 리깅과 애니메이션 API를 제공하지만,
Animation API는 Meshy에서 완료된 리깅 작업 ID를 요구한다. 해당 경로를 시험할 때는
별도 샘플에서 생성하고 게임 기준 리그로의 변환을 검증한다.
[Rigging API](https://docs.meshy.ai/en/api/rigging),
[Animation API](https://docs.meshy.ai/en/api/animation), 2026-09-28 확인.

비교 대상은 손가락·어깨·골반 변형, 무기 그립, 발 접지, 루프 연결, 루트 이동,
기존 팩과의 리타게팅, 작업 자동화 범위와 실제 소모 크레딧이다. 리깅 도구를 바꾸는
결정과 기존 애니메이션을 교체하는 결정은 분리한다. 새 동작을 추가하더라도 기존
클립 이름·공격 타이밍·서버 이동 규칙은 [애니메이션 파이프라인](ANIMATION.md)에 맞춘다.

2026-09-28 첫 샘플은 24본·손가락 본 없음으로 출력되었다. 기존 팩과 이름이 같은
본은 19개지만, `Spine`이 가리키는 척추 위치가 다르고 목 이름도 일치하지 않는다.
이 출력은 공통 리그로 채택하지 않으며, 손가락을 포함한 Mixamo 계열 기준 리그를
만드는 기본안을 유지한다. [제작 출처 기록](assets/modular-human-male-01.md#출처와-정리-범위).

### 원본과 출처

원화, 실제 프롬프트, Meshy 작업 ID와 생성 설정, 원본 모델·PBR 텍스처, 리깅 원본,
가공한 `.blend`, 재현 스크립트와 검증 결과를 제작 중에 보존한다. 최종 파일만 남기는
정리 요청을 받으면 채택한 에셋·편집 원본과 출처 기록을 유지하고 중간 작업물을 제거한다.
캐릭터·장비·애니메이션의
출처와 라이선스는 각각 [캐릭터](assets/characters.md), [아이템](assets/items.md),
[애니메이션](assets/animation.md) 문서에 기록한다. 생성일과 사용 등급을 함께 남기고,
ImageGen 등급은 지침의 ChatGPT Pro 20x를 사용한다. Meshy 등급은 생성 시 적용되는
사용자 확인 정보를 기록한다. 바이너리 배포는 [기존 에셋 배포 절차](ASSETS.md)를 따른다.

## 6. 데이터 설계

아래 이름과 구조는 구현을 위한 제안이며 아직 코드나 DB에 추가되지 않았다.

### 캐릭터 고유 외모

`CharacterAppearance`는 `version`, `body_type`, `face`, `hair_style`,
`hair_color`, `eye_color`를 갖는다. 첫 버전에서 체형과 얼굴은 값이 하나여도
명시적인 ID로 저장한다. 다음은 예시다.

```json
{
  "version": 1,
  "body_type": "human_standard_01",
  "face": "face_01",
  "hair_style": "short_01",
  "hair_color": "#443126",
  "eye_color": "#65815b"
}
```

기존 `gender`는 유지하고 허용되는 `body_type` 조합을 서버가 검사한다. 클래스는
게임 규칙을 결정하고, 외형 프리셋은 기본 외모·복장 선택에 사용한다. 기존 클래스의
성별 선택 범위나 시작 장비를 이 작업에서 바꾸지 않는다.

DB에는 nullable `appearance_json`을 추가하는 안을 사용한다. NULL은 기존 모델
경로를 뜻한다. 캐릭터 생성 트랜잭션에서 검증된 외모를 함께 저장하고,
`CharacterRecord` → 캐릭터 목록 → 입장 플레이어 데이터에 전달한다. 신규 요청의
미지원 버전·ID·색 형식·조합은 저장 전에 거부한다. 색은 소문자 `#rrggbb`로 정규화한다.

외모 카탈로그는 서버와 클라이언트가 같은 데이터 원본을 읽는다. ID는 출시 후
다른 의미로 재사용하지 않는다. 읽기 시 알 수 없는 저장값은 데이터를 덮어쓰지 않고
로그와 표시용 기본값으로 처리한다. 지원하지 않는 버전·체형이면 외모 전체를 기존
클래스 모델로, 알려진 체형의 미지원 헤어·얼굴·색이면 그 체형의 기본값으로 표시한다.
서버가 해석한 표시용 값을 모든 화면에 전달하고 원본 JSON은 보존한다. 위치·능력치의
주기 저장이 이 표시용 값을 원본 외모에 덮어쓰지 않게 한다.

### 아이템과 파츠 연결

`items.csv`에 선택적인 `equipmentVisual` ID를 추가하고 기존 CSV→JSON 생성 경로로
배포한다. 바닥에 놓인 아이템의 `worldModel`과 착용 중 변형되는 모델을 구분한다.

외형 카탈로그는 ID별로 체형에 맞는 파츠, 필요한 `rig_id`, 가림 영역, 헤어 정책을
지정한다. 한 아이템 외형이 여러 파츠를 포함할 수 있고, 여러 아이템이 같은 외형을
재사용할 수 있다. 클라이언트는 서버가 보낸 아이템 정의 ID에서 이 정보를 찾는다.
클라이언트가 임의 모델 URL이나 가림 규칙을 서버에 지정하지 않는다.

기본 복장은 체형별 카탈로그에 둔다. 나중에 방어구 염색을 추가하면 색은 캐릭터가
아닌 아이템 인스턴스에 저장하며 [망토 커스터마이제이션](CAPE_CUSTOMIZATION.md)의
거래·드랍·저장 원칙을 따른다.

## 7. 서버와 네트워크

`CreateCharacter`의 선택적 `appearance`와 캐릭터 목록·게임 입장 데이터의 외모
필드를 추가한다. 외모가 없으면 기존 경로로 처리해 agent-client와 기존 NPC 생성
경로도 유지한다. 생성 후 외모 변경 메시지는 미용 기능을 구현할 때 추가한다.

`VisibleEquipment`에는 `head`, `shirt`, `chest`, `hands`, `pants`, `boots`를
추가한다. 서버의 `read_visible_equipment`와 `PREVIEW_EQUIP_SLOTS`를 함께 확장해야
캐릭터 선택 화면이 실제 장착 상태와 일치한다.

게임 중에는 위 여섯 슬롯의 완전한 스냅샷을 담는 방어구 외형 상태와 변경 메시지를
추가한다. 초기 입장·시야 진입·재접속에도 같은 상태를 포함한다. 기존 무기·망토
메시지는 유지하고, 새 방어구 상태는 해당 슬롯만 소유해 중복된 상태 원본을 만들지 않는다.

장착 처리 후 `set_player_gear`가 서버 인벤토리로 새 상태를 계산하고, 바뀐 경우에만
주변 플레이어에게 보낸다. 슬롯 해제는 명시적인 null로 전달한다. 본인 화면은 서버의
인벤토리 응답에서 같은 외형 계산 함수를 사용한다. 에셋 로딩 실패는 서버 장착 결과를
되돌리지 않는다. 메시지 이름은 구현 시 확정한다.

프로토콜 변경 시 `PROTOCOL_VERSION`과 관련 Rust·TypeScript·agent-client 처리를
함께 갱신하고 브라우저의 공유 Rust WASM 직렬화 모듈도 다시 빌드한다. 저장 데이터에는
기본값 처리를 추가하지만, 이것만으로 구버전 클라이언트와의 접속 호환성이 보장된다고
간주하지 않는다.

## 8. 클라이언트 조립과 수명 관리

`PlayerModel`과 `CharacterPreview`가 함께 사용하는 조립 모듈을 둔다. 입력은
캐릭터 외모와 서버에서 확정된 장비이고, 출력은 기준 리그에 연결된 파츠와 가림 상태다.

1. 기준 몸체와 뼈대를 캐릭터별로 복제하고 기존 애니메이션을 연결한다.
2. 외모·장비 카탈로그에서 필요한 파츠와 기본 복장을 결정한다.
3. 파츠를 로드하고 `rig_id`·조인트·bind 정보를 검사한다.
4. 교체에 필요한 파츠가 준비되면 메시와 가림 상태를 함께 반영한다.
5. 제거된 파츠의 참조를 해제하고 사용하지 않는 자원을 정리한다.

로딩 중에는 마지막으로 완성된 외형을 유지한다. 처음 로드할 때는 완성된 기본
복장을 사용한다. 교체 실패 시 해당 슬롯의 기본 복장으로 수렴하고, 로드되지 않은
장비 때문에 몸체만 숨겨지는 일이 없게 한다. 기준 몸체까지 실패하면 기존 클래스
모델로 표시한다. 빠르게 장비를 바꿀 때는 요청 세대를 비교해 늦게 도착한 이전
파츠가 최신 장착 결과를 덮어쓰지 않게 한다.

파츠 교체와 색 변경으로 AnimationMixer나 현재 재생 시간을 초기화하지 않는다.
리타게팅은 기준 몸체·리그를 기준으로 수행하고, 장비 조합마다 다시 계산하지 않는다.
조립 모듈은 기준 스켈레톤과 애니메이션용 기준 메시를 명시적으로 보관한다.
현재 `findPrimarySkinnedMesh`의 본 개수 기준 탐색과 지오메트리 기반 캐시가
교체 파츠·망토를 기준으로 선택하지 않도록 모듈형 경로에 이 참조를 전달한다.
몸체 영역을 숨겨도 기준 리그와 메시 참조는 유지한다.

신발은 기준 발 접지 높이를 맞춰 제작하고, 기본 신발을 포함한 기준 자세에서 접지
보정을 한 번 계산한다. 장착만으로 캐릭터 월드 위치가 튀지 않게 한다. 기존 접지·시체
높이 계산은 숨겨진 메시도 순회하므로, 시체 접지에는 현재 표시되는 몸체·의상만
전달하고 망토와 제거된 파츠를 제외한다. 생성·선택 미리보기에도 같은 기준을 적용한다.

망토의 몸체 맞춤은 체형과 표시 중인 갑옷의 형태를 반영한다. 기존 `modelPath`만
사용하는 맞춤 캐시를 그대로 쓰면 상의 교체 후 이전 표면을 기준으로 움직일 수 있다.
모듈형 경로는 맞춤에 영향을 주는 파츠 ID를 캐시 키에 포함하고 형상 교체 시 갱신한다.
머리색·눈색·망토색 변경은 이 갱신을 발생시키지 않는다.

지오메트리·텍스처는 공유하고 뼈대는 캐릭터별로 소유한다. 색이 다른 플레이어가
공유 재질을 직접 수정하지 않도록 색별 재질 또는 인스턴스별 색 매개변수를 사용한다.
재질 캐시는 참조 수를 관리하고 마지막 사용자가 사라질 때 해제한다. 파츠 제거 시
다른 캐릭터가 사용 중인 공유 지오메트리·텍스처를 dispose하지 않는다.
현재 `loadGLB` 캐시는 원본을 계속 보관하므로, 캐시에 남아 있는 원본을 인스턴스
해제 과정에서 dispose하지 않는다. 모듈형 파츠의 원본 캐시는 참조 수를 관리하고,
미사용 원본의 보관 용량에 한도를 둔다. 사용자가 없는 원본을 캐시에서 제거할 때만
그 소유 자원을 해제한다. 재매핑한 지오메트리도 같은 규칙을 따른다.

최적화는 조립 모델의 드로우콜·삼각형·텍스처 메모리·최초 로딩 시간과 다수 캐릭터의
프레임 시간을 측정한 뒤 진행한다. 첫 구현에서 조합별 통합 메시를 미리 만들거나
매 프레임 메시를 병합하지 않는다. 필요하면 이후 장비 변경 시 병합, 아틀라스,
거리에 따른 단순화와 갱신 빈도 조절을 검토한다.

## 9. UI와 기존 캐릭터 전환

생성 화면에 헤어 스타일과 머리색·눈색 선택을 추가한다. 색 견본과 색 선택기를
제공하고, 눈색은 얼굴을 확인할 수 있는 확대 미리보기에서 보여준다. 선택 중에는
로컬 미리보기만 갱신하고 생성 확정 시 외모를 한 번 전송한다. 색 변경으로 능력치
굴림 결과를 초기화하지 않는다. 성별·클래스 변경으로 선택지가 무효가 되면 호환되는
기본값으로 바꾸고 화면에 바로 반영한다.

첫 버전의 체형·얼굴은 지원되는 클래스·성별 조합에서 고정한다. 생성 미리보기는
기본 복장과 실제 지급될 시작 장비를 반영하며, 생성 확정 후에는 서버가 돌려준 외모와
장착 스냅샷으로 전환한다. 미리보기에서 장비를 보여주는 것과 새 아이템 지급은 구분한다.

모듈형 외모가 있는 캐릭터만 새 조립 경로를 사용한다. 첫 체형이 지원되는 생성
선택지에서 기능을 제공하고, 나머지 클래스·성별과 기존 캐릭터는 기존 모델을 유지한다.
정확한 첫 체형과 대상 클래스는 원화·리그 샘플 검토에서 결정한다.

기존 캐릭터를 나중에 전환할 때는 미리보기와 선택 확정을 거친다. 기존 일체형 모델의
갑옷은 실제 보유 아이템과 다를 수 있으므로 자동으로 장비를 지급하거나 외형을 추측해
변환하지 않는다. 출시 후 카탈로그에서 참조 중인 체형·기본 파츠는 유지하며, 에셋을
먼저 배포한 뒤 새 ID를 선택 가능하게 한다.

## 10. 단계와 완료 기준

| 단계 | 산출물 | 완료 기준 |
| --- | --- | --- |
| 1. 에셋 샘플 | 기준 몸체·리그, 기본 복장, 헤어 2종, 상의 2종, 장갑·바지·부츠 | Blender와 게임용 미리보기에서 같은 리그로 조립·색 변경·동작 확인 |
| 2. 클라이언트 조립 | 공용 조립 모듈, 가림 규칙, 로딩·해제 처리 | 선택 화면과 인게임에서 일치하고 교체가 애니메이션을 끊지 않음 |
| 3. 저장과 동기화 | 생성 요청, DB, 외모·장비 스냅샷과 변경 방송 | 두 클라이언트·재접속·선택 화면에서 동일 결과, 기존 캐릭터 유지 |
| 4. 생성 UI | 스타일·색 선택과 미리보기 | 선택·확정·취소·오류 처리 확인, 서버 검증과 선택 범위 일치 |
| 5. 확장 | 추가 체형·장비·투구·치마 | 새 조합 검증과 성능 측정 후 순차 공개 |

첫 기능 완료에는 1~4단계가 필요하다. 제작 자동화의 가장 큰 불확실성은 생성된
형상의 맞춤과 관절 변형이므로, 1단계에서 작업량과 품질을 먼저 확인한다.

### 검증 항목

- 헤어·홍채만 색이 바뀌고 다른 캐릭터나 피부·흰자는 변색되지 않는다.
- 얼굴 확대 미리보기에서 눈꺼풀·코·입술·턱선의 형태와 윤곽을 확인한다.
  압축된 텍스처에서도 홍채와 얼굴 디테일이 유지되는지 확인하고, 모든 조립 파츠의
  삼각형 합계와 얼굴에 배분한 수를 함께 기록한다.
- 상의 교체, 장갑·부츠 착탈, 빈 슬롯과 미지원 외형의 기본 복장이 정상이다.
- 옷 경계가 벌어지거나 몸체가 사라지지 않는다. 부츠와 바지, 셔츠와 갑옷의
  가림 상태가 여러 장비를 차례로 입고 벗어도 일관된다.
- idle·walk·run·jump·공격·죽음·앉기·낚시·탑승에서 관절, 무기 그립과 발 접지를
  확인한다. 첫 세트는 헤어·상의의 모든 조합을 확인한다.
- 파츠 로딩 실패·빠른 연속 교체·캐릭터 제거 중 로딩 완료를 재현해 오래된 파츠,
  빈 몸체, 자원 누수가 생기지 않는지 확인한다.
- 저장 후 재접속, 시야 밖에서 장비 변경 후 진입, 두 클라이언트, 캐릭터 선택
  미리보기에서 외형이 일치한다. 잘못된 ID·색·버전·체형 조합은 저장 전에 거부한다.
- 기존 캐릭터·NPC·agent-client 생성 경로와 무기·망토 염색·텍스처가 유지된다.
- DB의 NULL·미지원 외모 데이터를 읽어도 원본을 덮어쓰지 않는다. 공유 WASM을 포함한
  브라우저와 서버 간 직렬화 왕복을 확인하고, 구버전 접속에는 갱신 안내가 나온다.
- 상의를 바꿔도 기준 리그·무기 부착점이 유지되고 망토가 새 갑옷 표면에 맞는다.
  가려진 몸체·의상이 접지 계산을 바꾸지 않으며, 반복 교체 후 캐시의 미사용분은
  보관 용량 한도 내에 머문다.
- 같은 환경에서 기존 모델과 모듈형 모델을 각 1·10·50명 표시해 로딩 시간,
  드로우콜, 메모리와 프레임 시간을 비교하고 첫 체형의 성능 예산을 확정한다.

자동 검증은 카탈로그 참조·리그 계약·가림 계산·저장 왕복·방송 상태·비동기 교체처럼
회귀 위험이 있는 부분에 집중한다. 관절 변형과 경계 품질은 포즈 렌더와 실제 화면으로
확인한다. 구현 시 프런트엔드 변경은 `npm run check`와 `npm run lint`, Rust 변경은
`cargo fmt`와 `cargo check`를 실행한다.

## 11. 샘플 제작에서 확정할 사항

- 첫 체형·대상 클래스, 얼굴과 두 헤어의 원화 방향
- 기준 리그의 본 목록, 몸체 비율과 파츠 경계
- 몸체 가림 영역의 실제 분할과 초기 의상 조합
- Meshy 리깅 샘플의 품질·호환성·비용과 채택 여부
- 총 15,000~20,000폴리곤 목표 안에서 얼굴·파츠별 배분과 재질·텍스처·다수 캐릭터 성능 예산

이 항목은 샘플 검증 후 문서에 결과를 기록한다. 현재 문서는 실제 생성 비용,
작업 기간, 전 장비의 외형 지원 시점을 확정하지 않는다.
