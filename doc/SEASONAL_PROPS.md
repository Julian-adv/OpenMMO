# 계절 장식

현실 달력의 특정 기간에만 월드에 서는 장식. 장식은 이벤트에 묶이고, 이벤트의 기간이 장식을 세우고 내린다.
첫 이벤트는 `winter`, 첫 장식은 앨더마크 광장의 겨울 나무다.

## 표

`data-src/seasonal_events.csv` 한 줄이 이벤트 하나다.

| 열 | 뜻 |
|---|---|
| `id` | 이벤트 id. 운영자 명령과 저장된 기간이 이 id를 쓴다. |
| `startMonth`, `startDay` | 기본 기간의 첫날 (포함) |
| `endMonth`, `endDay` | 기본 기간의 마지막 날 (포함). 시작보다 앞이면 해를 넘긴다. |

`data-src/seasonal_props.csv` 한 줄이 장식 하나다.

| 열 | 뜻 |
|---|---|
| `id` | 장식 id. 정렬 순서가 배치 id를 정하므로 한번 정하면 바꾸지 않는다. |
| `event` | 이 장식을 세우는 이벤트 id |
| `object` | `data/object_catalog.json`의 오브젝트 id |
| `x`, `z`, `rotation` | 월드 좌표와 회전(도). 높이는 서버가 부팅 때 지형에서 읽는다. |

현재 행: 이벤트 `winter` 11월 24일 ~ 1월 5일, 장식 `winter_tree_aldermark` (-1467, 4752).
시작일은 이 기능을 넣은 날이다. 기간 안에 배포되면 서버가 뜨는 순간 나무가 서도록 일부러 지난 날짜로 잡았다 (사용자 확인 2026-11-24).

## 기간

이벤트는 표의 기본 기간에 열린다. 운영자는 서버를 내리지 않고 이벤트마다 기간을 바꿀 수 있다.

| 설정 | 동작 |
|---|---|
| 기본 기간 | 표의 날짜를 따른다. |
| 기간 지정 | 운영자가 정한 시작일 ~ 종료일. 표의 날짜를 대신하고 매년 반복된다. |
| 끄기 | 기간과 무관하게 서지 않는다. 다시 켤 때까지 유지된다. |

- 채팅 명령 (관리자): `/season`은 패널을 연다. `/season <이벤트> <MM-DD> <MM-DD>`, `/season <이벤트> off`,
  `/season <이벤트> default`는 바로 적용하고 현재 상태를 한 줄로 답한다.
- 관리자 화면 왼쪽 위, 디버그 버튼 옆의 달력 버튼과 디버그 패널의 SEASON 버튼도 같은 패널을 여닫는다 (`FPSCounter.svelte`).
- 패널 (`SeasonalEventsPanel.svelte`): 이벤트별 상태, 기본 기간, 장식 수를 보이고 설정을 고쳐 적용한다.
  적용 전에 오늘 서는지 내려가는지 미리 알려 준다. `QuerySeasonalEvents`/`SetSeasonalEvent`로 묻고 `SeasonalEvents`로 답을 받는다.
  두 요청은 Debug* 메시지처럼 관리자 연결만 통과한다 (`connection.rs`의 `requires_admin`).
- 설정은 `seasonal_event_schedules` 테이블에 저장한다. 행이 없으면 기본 기간, 날짜가 NULL이면 끄기다.
  DB에 먼저 쓰고 월드에 반영하므로, 화면에 보이는 설정은 재시작 뒤에도 남는다.
- 기간을 한 해만 쓰려면 시즌이 끝난 뒤 기본 기간으로 되돌린다.

## 동작

- 날짜는 한국 시간(UTC+9) 날짜다. 게임 내 달력과 무관하다. 자정에 날이 바뀌고, 매시 정각 확인이라 장식은 자정 직후에 서고 내려간다.
- 서버는 부팅 때와 매시간 날짜를 확인한다. 날짜나 운영자 설정이 바뀌어 장식이 서거나 내려가면
  그 리전의 충돌을 다시 계산하고 `ObjectRegionsChanged`를 모든 접속자에게 보낸다.
- 웹 클라이언트는 그 리전의 캐시를 버리고, 지금 보고 있는 리전이면 다시 읽어 눈앞에서 장식을 세우고 내린다
  (`objectManager.invalidate`, `ObjectOverlay`). 요청이 한꺼번에 몰리지 않게 2초 안에서 흩어 보낸다.
  agent-client는 그 리전의 가구를 다시 받아 경로 계산에 쓴다.
- 기간 안의 장식은 필드 보스 제단과 같은 고정 배치로 들어간다. 리전 오브젝트 파일에 저장하지 않고,
  `GET /api/terrain/objects`가 `fixed: true`로 덧붙여 내려보내며, 에디터 저장(`PUT`)은 이를 걸러낸다.
- 배치 id는 `FIXED_PLACEMENT_ID_BASE`(20억) + 1억부터다. 필드 보스 id와 겹치지 않는다.

## 겨울 나무 (`winter_tree`)

- 모델은 `client/public/models/objects/winter_tree.glb`. 높이 6.2m, 가지가 땅까지 내려오는 전나무에 금빛 장식 줄·구슬·별이 달리고
  밑에는 붉은 치마 천 위로 선물 상자가 쌓였다.
  출처와 가공은 [props.md](assets/props.md)에 있다 (David Montaña, CC BY 4.0).
- 카탈로그의 `glow: "winterTree"`가 나무를 꾸민다 (`client/src/lib/utils/winter-tree.ts`).
  - 전구 70개의 색 빛무리. 밝은 띠가 나선으로 나무를 타고 오른다.
  - 꼭대기 별의 옅은 빛무리와 천천히 흔들리는 십자 광채. 처음 세기는 과하다는 평이라 절반 아래로 낮췄다 (사용자 확인 2026-11-24).
  - 가지 위에서 잠깐씩 반짝이는 광채 18개, 나무 둘레로 천천히 가라앉는 금가루 28개.
  - 별과 구슬은 밤에 제 색으로 빛난다 (재질 발광).
  - 낮에는 가지를 짙은 전나무색으로 낮추고 잎 조각을 더 넓게 오려 풍성하게 그리며, 속 몸통을 어둡게 한다.
    햇빛에서는 잎이 연두색으로 뜨고 성겨서 부스스해 보인다는 평이었다 (사용자 확인 2026-11-24).
    밤에는 이 보정이 0이라 모델 그대로다. 같은 밤 조건에서 전후가 같음을 확인했다.
  - 눈이 쌓이면 가지 윗면에 눈이 얹힌다. 지형의 눈 덮임 값(`snowCover`)을 그대로 따르므로 눈이 녹으면 같이 사라진다.
    지형용 눈 무늬는 폭이 몇 미터라 나무 한쪽만 하얗게 뭉쳐서, 나무 자체 좌표의 잔무늬로 고르게 얹는다.
    눈밭 한가운데서 나무만 말끔한 것이 어색하다는 평이었다 (사용자 확인 2026-11-24).
  - 밤에는 나무가 주변 바닥과 캐릭터에 따뜻한 빛을 던진다. 지상에서 쉬는 수정 빛 풀의 조명을 빌려 써서
    장면의 조명 수는 늘지 않는다 (`GameScenePlayersLayer.svelte`의 `TREE_GLOW`). 횃불 효과를 끈 그래픽 설정에서는 꺼진다.
  - 모두 셰이더 시간으로 움직여서 프레임마다 도는 스크립트가 없다. 드로콜은 5회 늘고, 밤에 진하고 낮에 옅다.
- 선물 더미를 덮는 3.4m 사각형이 통행을 막는다. 치마 천 가장자리는 밟고 지나간다.

## 장식 추가

1. 오브젝트를 카탈로그에 등록한다. 통행을 막으려면 `solid`를 준다. `footprint`를 함께 주면 모델 경계 상자 대신 그 범위만 막는다.
2. `data-src/seasonal_props.csv`에 행을 추가하고 `event`에 묶을 이벤트를 적는다.
   새 이벤트면 `data-src/seasonal_events.csv`에 행을 추가하고, 패널에 보일 이름을 로케일의 `season.event.<id>`에 넣는다.
3. 좌표는 운영 서버의 실제 배치를 기준으로 확인한다. 마을 건물은 리전 데이터라 저장소에 없다.
