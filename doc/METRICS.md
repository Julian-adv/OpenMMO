# 운영 지표

## 접근 권한

대시보드와 지표 API는 운영자 전용입니다. 모든 `/api/metrics/` 요청에 Google ID 토큰을 `Authorization: Bearer <token>`으로 전달해야 하며, 검증된 이메일이 서버의 `ADMIN_EMAILS` / `--admin-emails`에 포함된 계정만 허용합니다. 일반 계정·미인증 이메일은 403, 누락·위조·만료된 토큰은 401입니다. NPC 토큰과 게임 세션 토큰은 사용할 수 없습니다. 성공·인증 실패 응답 모두 `Cache-Control: no-store`입니다.

`GET /api/metrics/session`은 같은 권한 검사를 거쳐 204를 반환하며 로그인 화면에서 사용합니다. Google 인증 또는 관리자 목록이 설정되지 않으면 조회를 허용하지 않습니다. 설정 방법은 [대시보드 안내](../dashboard/README.md#접근-권한)를 참고하세요.

## 동시 접속 계정 수

- 로그인한 뒤 게임에 입장했고, 현재 세션과 플레이어가 모두 남아 있는 계정을 셉니다. 로그인·캐릭터 선택 화면의 계정은 제외합니다.
- 계정당 하나인 서버의 현재 세션을 기준으로 하므로 중복 로그인을 두 번 세지 않습니다.
- `is_official_npc`인 공식 NPC는 제외합니다. 일반 플레이어의 외부 에이전트 접속은 포함하며 사람/봇을 추정해 분류하지 않습니다.
- 접속 핸드셰이크의 `ClientKind::Web`은 웹 접속(초록), `Cli`는 외부 에이전트(보라), `Other`·`Unknown`은 기타·미분류(회색)로 표시합니다. 클라이언트가 보고한 프로그램 종류 기준이며 실제 조작자가 사람인지 AI인지는 판별하지 않습니다.
- 현재 접속 카드와 그래프 툴팁은 합계 및 유형별 계정 수·비율을 표시합니다. 그래프는 유형별 누적 영역과 합계 선으로 표시하며, 기간 최고·평균 카드의 합계 계산은 유지합니다.
- 접속 종료가 서버에 반영되면 제외합니다. 네트워크 단절을 감지하기 전에는 세션이 잠시 집계에 남을 수 있습니다.
- `current`는 API 요청 시점의 접속 수입니다. 그래프와 기간 최고·평균은 1시간 간격 관측값이므로 짧은 접속 증가가 최고값에 잡히지 않을 수 있습니다.

이 지표는 일정 기간 동안 접속한 서로 다른 계정 수인 DAU/WAU/MAU와 다릅니다. 대시보드 조회 기간은 최근 1일, 1주일, 1개월, 6개월, 1년이며 기본값은 1일(최근 24시간)입니다. 최고·평균은 선택한 기간 안에서 실제로 수집한 표본만 사용합니다. 1개월·6개월·1년은 각각 최근 30일·180일·365일입니다. 기록이 없으면 최고·평균을 `—`로 표시하고, 실제 0명인 표본은 `0`으로 표시합니다.

## 수집과 저장

게임 서버가 REST API를 연 뒤 즉시 한 번, 이후 매 정각에 접속 수를 읽어 기존 계정 SQLite DB의 `concurrent_account_samples`에 저장합니다. 기본 키는 관측 시각을 시간 단위로 내린 Unix 초입니다. 같은 시간에 재시작·정상 종료하면 해당 시간의 마지막 관측값으로 갱신합니다. 기존 분 단위 이력은 보존하며 조회할 때 시간 단위로 묶습니다.

스키마는 `AuthService` 초기화에서 자동 생성되고 기존 계정·캐릭터 데이터를 변경하지 않습니다. 서버 재시작 후에도 기록이 유지됩니다. 현재는 기록을 자동 삭제하지 않으며, 새 기록은 하루 최대 24행입니다.

`web_accounts`와 `agent_accounts` 열은 자동 추가되며, 이전 합계 기록은 두 열이 `0`인 채 보존됩니다. 기타·미분류는 `accounts - web_accounts - agent_accounts`입니다. 과거 비율을 추정해 채우지 않으며, 새 서버에서 수집하는 기록부터 유형별 구성이 저장됩니다.

수집을 도입하기 전이나 서버가 꺼져 있었던 구간에는 표본이 없습니다. 수집 실패도 0으로 기록하지 않습니다. 대시보드는 표본이 없는 표시 구간에서 선을 끊습니다. 긴 기간은 구간 내 실제 표본의 평균을 그리므로 같은 구간 안의 짧은 수집 중단은 선에 나타나지 않습니다. 기존 접속 로그로 과거 수치를 역산하거나 채워 넣지 않습니다.

## API

```http
GET /api/metrics/concurrent?hours=24
```

`hours`는 아래 값을 지원하며 생략 시 `24`입니다. 나머지 값은 HTTP 400입니다. 기존 REST 포트(기본 10007)에서 제공하는 운영자 전용 읽기 API이며 계정 이름이나 캐릭터 식별자를 반환하지 않습니다. 저장소 조회 실패는 HTTP 503으로 응답합니다. 성공 및 저장소 오류 응답에는 `Cache-Control: no-store`를 지정합니다.

| 조회 기간 | hours | 그래프 간격 |
| --- | ---: | --- |
| 1시간 / 6시간 / 24시간 | 1 / 6 / 24 | 1시간 |
| 1주일 | 168 | 1시간 |
| 1개월 (30일) | 720 | 1시간 평균 |
| 6개월 (180일) | 4320 | 6시간 평균 |
| 1년 (365일) | 8760 | 1일 평균 |

`sample_interval_seconds`는 그래프 집계 간격입니다. 구간은 Unix 초 기준으로 정렬하며, 첫 구간의 시작이 조회 범위보다 앞서면 `from`으로 표시합니다. 각 구간의 `accounts`는 실제 표본의 평균, `sample_count`는 표본 수, `peak_accounts`와 `peak_timestamp`는 원본 최고값과 최초 관측 시각입니다. 기간 평균은 표본 수로 가중 계산하며, 최고값과 기록 수 역시 원본 기준으로 유지합니다. 새 방식의 연간 시간별 기록은 최대 8,760행이며 약 365개 일평균 지점으로 반환합니다. 기존 분 기록도 조회할 수 있습니다.

`current`와 `samples`는 `web_accounts`, `agent_accounts`, `other_accounts`를 포함하며 세 값의 합은 `accounts`입니다. 장기 구간은 모든 유형을 같은 표본 수로 평균하므로, 분류 전후 기록이 섞인 구간도 합계가 보존됩니다. 비율은 구간별 유형 평균을 구간 합계 평균으로 나눈 값입니다. 접속 합계가 `0`이면 모든 비율을 `0%`로 표시합니다.

응답 예시:

```json
{
  "from": 1699913600,
  "until": 1700000000,
  "sample_interval_seconds": 3600,
  "current": { "timestamp": 1700000000, "accounts": 12, "web_accounts": 8, "agent_accounts": 4, "other_accounts": 0 },
  "samples": [
    { "timestamp": 1699992000, "accounts": 10, "web_accounts": 7, "agent_accounts": 3, "other_accounts": 0, "peak_accounts": 10, "peak_timestamp": 1699992000, "sample_count": 1 },
    { "timestamp": 1699995600, "accounts": 12, "web_accounts": 8, "agent_accounts": 4, "other_accounts": 0, "peak_accounts": 12, "peak_timestamp": 1699995600, "sample_count": 1 },
    { "timestamp": 1699999200, "accounts": 11, "web_accounts": 7, "agent_accounts": 4, "other_accounts": 0, "peak_accounts": 11, "peak_timestamp": 1699999200, "sample_count": 1 }
  ]
}
```

시간은 모두 UTC Unix 초입니다. `samples`는 `[from, until]` 범위의 기록을 시간 오름차순으로 반환합니다. 대시보드는 한국 시간(`Asia/Seoul`, KST)으로 표시하고 매 정각 5초 후 갱신합니다. 최초 접속·기간 변경·수동 새로고침은 즉시 조회합니다. 네트워크 오류 시 마지막 수신 시각과 갱신 중단 상태를 표시하며, 이전 값을 현재 값인 것처럼 표시하지 않습니다.

## 유니크 접속 계정 추이

동시 접속 추이 아래에 일별 유니크 계정 그래프를 표시합니다. 매일 한국 시간 자정 기준으로 직전 1일·7일·30일·180일·365일 동안 게임에 머문 서로 다른 계정 수를 각각 집계합니다. 기간 선택은 1일, 1주일, 1개월, 6개월, 1년이며 1시간·6시간은 지원하지 않습니다. 화면에는 마지막 집계 기준 시각을 표시합니다.

계정 이름을 정규화해 재접속과 캐릭터 변경을 중복 제거하고 공식 NPC는 제외합니다. 해당 기간 전에 입장해 기간 안까지 접속을 유지한 계정도 포함합니다. 날짜별 숫자를 더하지 않고 각 기간의 계정을 한 번씩 세므로, 여러 날 접속한 계정도 한 계정입니다. 각 자정 `t`의 집계 범위는 `[t - 선택 기간, t)`이며 자정에 새로 입장한 계정은 다음 집계에 포함합니다.

게임 입장과 종료 시 `account_activity_sessions`에 접속 구간을 저장하고, 접속 중에는 매시간 마지막 확인 시각을 갱신합니다. 정상 종료 시 마지막 스냅샷도 저장합니다. 서버가 비정상 종료되면 마지막으로 저장한 시각까지만 접속한 것으로 처리합니다. 기록 실패는 서버 로그에 남으며, 저장되지 않은 접속은 집계에서 빠질 수 있습니다.

시간별 수집 작업에서 자정이 지난 뒤 처음 한 번 계정별 마지막 접속 시각을 읽어 다섯 기간의 값을 계산합니다. 결과는 `unique_account_daily_samples`에 날짜당 한 행으로 저장합니다. 이미 저장된 날짜는 재계산하지 않으며, 날짜별 집계와 저장은 한 트랜잭션으로 처리합니다. 실패하면 다음 수집 작업에서 다시 시도합니다.

서버 시작 시 게임·API 접속을 받기 전에 수집 시작 이후부터 가장 최근 한국 시간 자정까지 누락된 모든 날짜를 오래된 순서로 집계합니다. 기존 기록 사이에 빠진 날짜도 채우며, 이미 저장된 결과는 유지합니다. 서버가 며칠 꺼져 있었더라도 각 자정 기준의 접속 이력으로 다섯 기간을 각각 계산합니다. 서버 중단 기간에 새 접속이 없어도 주간·월간 집계에는 그 전에 접속한 계정이 포함될 수 있습니다. 보충 집계에 실패하면 오류를 기록하고 시작을 중단하며, 다음 시작 시 완료된 날짜는 건너뛰고 나머지를 처리합니다.

`unique_account_collection`의 최초 수집 시작 시각을 유지합니다. 첫 집계는 수집 시작 이후 처음 맞는 한국 시간 자정에 생성합니다. 이전 동시 접속 합계로 과거 이력을 추정하지 않으며, 선택 기간 전체의 이력이 없으면 화면과 툴팁에서 알립니다. 첫 집계 전에는 대기 상태, 집계된 날짜에 접속이 없으면 `0`, 집계하지 못한 날짜는 빈 구간으로 표시합니다. 기존 접속 이력과 집계 결과는 현재 자동 삭제하지 않습니다.

```http
GET /api/metrics/unique?hours=24
```

지원하는 `hours`는 `24 / 168 / 720 / 4320 / 8760`이며 기본값은 `24`입니다. 잘못된 기간은 HTTP 400, DB 조회 실패는 HTTP 503입니다. 성공·DB 오류 응답에는 `Cache-Control: no-store`를 지정합니다.

응답은 `from`, `until`, `window_seconds`, `sample_interval_seconds`, `collection_started_at`, `last_aggregated_at`, `samples`를 포함합니다. `until`은 요청일의 한국 시간 자정이고 `from`은 선택 기간만큼 앞선 자정입니다. `sample_interval_seconds`는 항상 `86400`이며, `last_aggregated_at`은 가장 최근 저장된 집계의 기준 시각입니다. 첫 집계 전에는 `null`입니다.

각 표본은 `{ "timestamp": 1700002800, "accounts": 12 }` 형식이며 계정 식별자는 공개하지 않습니다. 최대 표본 수는 선택 일수 + 1개입니다. 그래프 요청은 저장된 일별 숫자만 읽으며 접속 이력 조회나 중복 제거 계산을 실행하지 않습니다. 대시보드의 1시간 갱신과 새로고침도 일별 집계를 다시 실행하지 않습니다.

## 서버 총 골드 추이

DB와 API의 모든 금액 필드(`gold`, `total_gold`, `peak_gold`, `gold_per_account`, `peak_gold_per_account`)는 코퍼 단위입니다. `1골드 = 100실버 = 10,000코퍼`이며 순위 표·요약·그래프 축·툴팁은 `8g61s34c` 형식으로 표시합니다. g·s·c 금액에는 각각 금색·은색·구리색을 적용합니다. 0인 단위는 생략하고 전체가 0이면 `0c`를 표시하며 평균값은 가장 가까운 1코퍼로 반올림합니다. 저장된 데이터와 순위 계산에는 원래 코퍼 값을 사용합니다.

모든 캐릭터의 보유 골드 합계를 표시합니다. 접속 여부·최근 활동 여부와 관계없이 오프라인 캐릭터와 공식 NPC도 포함합니다. 아이템의 환산 가치는 포함하지 않습니다.

[물가 시스템](PRICING.md)의 기존 `gold_snapshots.total_gold` 시간별 기록을 재사용합니다. 서버는 캐릭터 변경 사항을 DB에 저장한 뒤 해당 시간의 집계를 한 번 기록하며, `ts`는 시간을 내림한 Unix 초입니다. 같은 시간의 기록을 덮어쓰지 않고, 대시보드 조회도 새 기록을 만들지 않습니다. 이미 저장된 과거 기록은 그대로 표시하고, 기록이 없는 표시 구간에서는 선을 끊습니다.

최근 총량은 마지막으로 저장한 집계값이며 실시간 잔액이 아닙니다. 화면에 마지막 집계 기준 시각을 함께 표시합니다. 첫 기록 전에는 `—`, 실제 합계가 0인 기록은 `0`으로 표시합니다. 1시간 보기에서는 보통 하나의 기록점이 표시됩니다.

```http
GET /api/metrics/gold?hours=24
```

| 조회 기간 | hours | 그래프 간격 |
| --- | ---: | --- |
| 1시간 / 24시간 | 1 / 24 | 1시간 |
| 1주일 | 168 | 1시간 |
| 1개월 (30일) | 720 | 1시간 |
| 6개월 (180일) | 4320 | 6시간 평균 |
| 1년 (365일) | 8760 | 1일 평균 |

기본 기간은 24시간입니다. 나머지 기간은 HTTP 400, DB 조회 실패는 HTTP 503이며 성공·DB 오류 응답에 `Cache-Control: no-store`를 지정합니다. 계정·캐릭터 식별자는 반환하지 않습니다.

응답은 `from`, `until`, `sample_interval_seconds`, `latest`, `samples`를 포함합니다. `latest`는 조회 기간과 무관하게 요청 시각 이전의 마지막 `{ timestamp, total_gold }`이며 첫 기록 전에는 `null`입니다. 각 그래프 표본은 `{ timestamp, total_gold, peak_gold, sample_count }`입니다. `total_gold`는 구간 내 실제 시간별 기록의 평균, `peak_gold`는 원본 최고값, `sample_count`는 기록 수입니다. 기록이 없는 시간을 0으로 채우지 않습니다. 구간은 Unix 초 기준으로 정렬하며, 첫 구간이 조회 시작보다 앞서면 `timestamp`를 `from`으로 표시합니다.

## 활성 유저 1인당 골드 추이

서버 총 골드 아래에 `시간별 서버 총 골드 ÷ 해당 날짜 자정의 활성 계정 수`를 표시합니다. 총 골드와 조회 기간을 공유하며, 별도 선택자로 분모인 직전 1일·7일·30일·180일·365일의 유니크 계정 수를 지정합니다. 기본값은 1일입니다. 총 골드는 오프라인 캐릭터와 NPC를 포함하고, 분모는 공식 NPC를 제외한 접속 계정입니다.

각 골드 기록은 그날 한국 시간 자정의 `unique_account_daily_samples`와 연결합니다. 해당 자정 이전의 선택 기간에 접속한 유니크 계정 수를 사용하며, 현재 계정 수를 과거 전체에 적용하거나 날짜별 계정 수를 더하지 않습니다. 일별 집계가 없거나 계정 수가 0인 시간은 계산에서 제외합니다. 6개월·1년 그래프는 시간별로 나눗셈을 먼저 계산한 뒤 구간 평균과 최고값을 구합니다. 골드가 0이고 계정 수가 양수인 기록은 실제 0으로 유지합니다.

```http
GET /api/metrics/gold-per-account?hours=24&active_hours=168
```

`hours`의 지원 값과 그래프 간격은 총 골드 API와 같습니다. `active_hours`는 독립적으로 `24 / 168 / 720 / 4320 / 8760`을 지원합니다. 두 매개변수 모두 생략 시 `24`이며 잘못된 값은 HTTP 400입니다. DB 오류는 HTTP 503이며 성공·DB 오류 응답에 `Cache-Control: no-store`를 지정합니다.

응답은 `from`, `until`, `sample_interval_seconds`, `window_seconds`, `collection_started_at`, `latest`, `samples`를 포함합니다. `window_seconds`는 활성 계정 집계 기간입니다. `latest`는 가장 최근 골드 기록에 대응하는 `{ timestamp, total_gold, accounts, gold_per_account }`이며 해당 날짜의 유효한 분모가 없으면 `null`입니다. 이때 이전 날짜의 값을 최신 값으로 대신하지 않습니다. 각 표본은 `{ timestamp, gold_per_account, peak_gold_per_account, sample_count }`이며 계산 가능한 시간별 기록만 평균·최고·기록 수에 포함합니다. 구간 정렬과 첫 부분 구간의 시각은 총 골드 API와 같습니다.

화면에는 최근 계산의 분자·분모와 골드·활성 계정 집계 시각을 표시합니다. 선택한 활성 기간의 접속 이력이 충분히 쌓이지 않은 구간은 수집 시작 시각과 함께 안내합니다. 조회는 저장된 골드와 일별 집계만 읽으며 새로운 집계나 접속 이력 계산을 실행하지 않습니다.

## 레벨 상위 10명

오프라인을 포함한 전체 캐릭터 중 공식 NPC 계정(`npc_` 접두사)을 제외하고, 저장된 레벨이 가장 높은 10명을 표시합니다. 계정별 중복 제거는 하지 않습니다. 레벨 내림차순, 동점이면 누적 경험치 내림차순, 둘 다 같으면 캐릭터 ID 오름차순으로 정렬하며 표시 순위는 1~10입니다. 캐릭터가 10명 미만이면 존재하는 캐릭터만 반환합니다.

```http
GET /api/metrics/level-leaderboard?hours=168
```

현재 DB의 순위와 해당 캐릭터들의 레벨 이력을 같은 읽기 트랜잭션에서 조회합니다. `hours`는 `168 / 720 / 4320 / 8760`이며 기본값은 `168`입니다. 다른 값은 HTTP 400입니다. 응답의 `timestamp`는 조회 시각, `from`은 선택 기간의 시작, `sample_interval_seconds`는 각각 `3600 / 3600 / 21600 / 86400`입니다.

`entries`는 `[{ "name": "모험가", "level": 12, "account_first_rank": 1 }]` 형식입니다. `account_first_rank`는 현재 표에서 같은 계정의 첫 캐릭터가 차지한 순위(1부터 시작)입니다. `series`는 같은 순서의 `[{ "name": "모험가", "started_at": 1700000000, "samples": [{ "timestamp": 1700000000, "level": 12 }] }]` 형식입니다. 계정 이름·캐릭터 ID는 노출하지 않습니다. 대상이 없으면 두 배열이 비어 있고, DB 조회 실패는 HTTP 503입니다. 성공·DB 오류 응답에 `Cache-Control: no-store`를 지정합니다.

같은 계정이 표에 여러 번 등장하면 두 번째부터 `Agent 1 (Jake 1)`처럼 첫 캐릭터명을 괄호 안에 표시합니다. 표 밖의 캐릭터와 생성 순서는 이 표시에 포함하지 않으며, 순위가 바뀌면 기준 캐릭터도 다시 정합니다.

대시보드는 1시간마다 순위를 갱신하고 수동 새로고침도 지원합니다. 접속 중 변경 사항은 기존 서버 저장 주기(보통 32초) 이후의 조회에 반영됩니다. API는 저장을 강제하거나 순위 이력을 생성하지 않습니다. 조회 실패 시 마지막 순위와 수신 시각을 유지하면서 갱신 중단을 표시합니다.

레벨 변화는 `character_level_history`에 캐릭터 ID·Unix 초·레벨로 저장합니다. 최초 적용 시 기존 일반 캐릭터의 현재 레벨을 적용 시각으로 기록하며, 과거 생성 시각으로 소급하지 않습니다. 새 캐릭터 생성 시 기준값을 기록하며, 이후에는 시간별 작업에서 직전 관측값과 달라진 레벨만 추가합니다. 32초 게임 저장 때마다 실행하던 변경 트리거는 제거합니다. 시간 사이의 중간 변화는 기록하지 않습니다. 상위 10명 외의 캐릭터도 기록하므로 이후 순위에 들어오면 기존 이력이 표시됩니다. 공식 NPC는 제외합니다. 이름 변경과 재시작 후에도 이력이 유지되며 캐릭터 삭제 시 외래 키 연쇄 삭제로 함께 정리됩니다. 남아 있는 캐릭터의 기록은 자동 삭제하지 않습니다.

그래프는 구간별 마지막 관측값을 수집 시각에 표시합니다. 기간 시작 이전 기록이 있으면 당시 마지막 레벨을 `from`의 기준점으로 사용하며, 기간 안에서 수집이 시작된 캐릭터는 최초 기록도 보존합니다. `started_at`은 그 캐릭터의 최초 수집 시각입니다. 다음 변경 전까지 마지막 레벨을 유지하는 계단선으로 그리며, 수집 시작 이전은 비워 둡니다. 장기 그래프에서는 같은 구간 안의 중간 레벨 변화가 생략될 수 있습니다. 캐릭터별 색상은 표·선·범례에서 같고, 선택한 캐릭터를 강조하며 작은 화면에서는 표와 그래프를 세로로 배치합니다.

시간별 캐릭터 지표 작업은 네 가지 이력을 한 트랜잭션에서 기록합니다. `character_metrics_state`에 마지막 성공 시각을 저장해 같은 시간에 재시작해도 중복 기록하지 않으며 실패하면 성공 시각도 갱신하지 않습니다. 변하지 않은 캐릭터는 행을 추가하지 않습니다. 순위 표는 현재 저장된 상태를 조회하므로 수동 새로고침 시 시간별 그래프의 마지막 관측값과 다를 수 있습니다.

## 골드 생산 순위

활성 유저 1인당 골드 아래에 새로 생성된 골드를 생산원별로 합산한 표를 표시합니다. 상인 판매는 아이템 종류별로, 나머지는 던전 보상 상자·동전 더미 획득·동전 주머니 개봉·주민 NPC 급여로 묶습니다. 생성 골드 내림차순, 동점이면 생산원 코드·아이템 ID 오름차순입니다. 각 행은 순위·생산원·수량 또는 횟수·생성 골드·전체 생산액 대비 비중입니다. 판매는 개수, 보상은 실제 지급 횟수를 표시하며 금액은 코퍼 단위로 계산하고 기존 g/s/c 형식으로 표시합니다.

대시보드 조회 기간은 1일·1주일·1개월·6개월·1년이며 기본값은 1일(24시간)입니다. 완료된 시간대만 포함합니다.

상인 단일·묶음 판매의 실제 지급액(흥정 포함), 던전 최종 보상 상자의 골드, 몬스터·일반 상자·파괴물 등에서 나온 동전 더미를 주운 금액, 동전 주머니를 열어 얻은 금액, 지갑 상한을 적용한 주민 NPC의 실제 급여 지급액을 기록합니다. 전리품이 바닥에 생성되기만 한 경우에는 집계하지 않습니다. 실패하거나 중복된 획득과 급여 미지급은 집계하지 않습니다. 공식 NPC가 얻은 골드도 포함합니다.

주민 NPC의 보유 지갑에서 지불한 거래, 플레이어 간 거래와 팁은 기존 골드의 이동이므로 제외합니다. 아이템 판매는 획득 경로와 강화·염색을 구분하지 않고 아이템 정의 ID로 묶습니다. 재매입 등 소비한 골드는 총생산량에서 차감하지 않으므로 서버 전체 골드의 순증가량과는 다릅니다.

```text
GET /api/metrics/item-gold-sources?hours=24
```

기존 API 경로를 유지합니다. `hours`는 `1 / 24 / 168 / 720 / 4320 / 8760`을 지원하며 기본값은 `24`입니다. 잘못된 값은 HTTP 400, DB 오류는 HTTP 503입니다. 성공·DB 오류 응답은 `Cache-Control: no-store`를 지정합니다. 응답은 `from`, `until`, `collection_started_at`, `rewards_started_at`, `total_gold`, `entries`를 포함합니다. 각 행은 `{ source, name, quantity, gold }`이며 `source`는 `item_sale / dungeon_chest / coin_pile / coin_pouch / npc_salary`입니다. 판매 행만 `item_def_id`를 추가로 포함하고 이름은 현재 아이템 정의, 정의가 사라졌으면 ID를 사용합니다. `total_gold`는 모든 행의 합계입니다. 계정·캐릭터 정보는 반환하지 않습니다.

조회 종료 `until`은 현재 시각을 정각으로 내린 값이고 `from = until - hours × 3600`입니다. 시작은 포함하고 종료는 제외하는 `[from, until)` 범위이며 기록이 없으면 빈 목록과 총액 0을 반환합니다.

기존 `item_sale_samples` 테이블을 확장해 시간대 시작 Unix 초·생산원·아이템 ID별 수량과 지급액을 저장합니다. 판매 이외의 아이템 ID는 빈 문자열입니다. 메모리에서도 같은 시간·생산원을 합산하고 다음 정각에 완료된 시간대를 하나의 트랜잭션으로 저장합니다. 32초 게임 저장과 로그아웃은 이 집계를 저장하지 않으며 로그아웃 후에도 대기 집계를 유지합니다. 실패한 집계는 복원해 다음 시간에 재시도하고 정상 서버 종료 시 진행 중인 시간대까지 저장합니다. 비정상 종료 시 아직 저장하지 않은 통계는 유실될 수 있습니다.

기존 초 단위 판매는 합계를 보존해 시간 단위로 합치고, 기존 판매 기록에는 `item_sale` 생산원을 지정합니다. 이전 판매의 수집 시작 `collection_started_at`은 유지하며 판매 외 골드의 수집 시작은 별도 `rewards_started_at`으로 저장합니다. 두 시각 모두 재시작 후에도 유지합니다. 과거 보상을 추정해 채우지 않으며 조회 기간이 각 수집 시작보다 앞서면 화면에 안내합니다. 캐릭터 삭제와 관계없이 집계는 보존하고 조회 자체는 기록을 생성하지 않습니다.

## 골드 소모 순위

골드 생산 순위 바로 아래에 실제 소모한 골드를 항목별로 표시합니다. 상인 단일·묶음 구매는 흥정·물가 반영 후 실제 지불액과 구매 수량을 아이템별로 합산합니다. 상인 재매입은 같은 아이템의 일반 구매와 별도 행으로 표시합니다. 가판 거래는 판매자에게 넘어간 대금을 제외하고 거래 전체에 부과한 수수료만 한 번 기록합니다. 토지세는 영지별 납부 횟수, 체납 복구 비용은 복구 횟수를 표시합니다. 면세·미납·실패한 구매는 제외하며 공식 NPC의 소모도 포함합니다.

주민 NPC·플레이어 간 거래와 팁, 토지 세금 계좌 입출금은 기존 골드의 이동이므로 제외합니다. 세금 계좌에서는 실제 세금과 복구 비용으로 차감된 금액만 소모입니다. 생산 순위에서 이 금액을 차감하지 않습니다.

각 행은 순위·소모 항목·수량 또는 횟수·소모 골드·비중입니다. 소모액 내림차순, 동점이면 항목 코드·아이템 ID 오름차순입니다. 대시보드는 기본 1일이며 1일·1주일·1개월·6개월·1년을 생산 순위와 독립적으로 선택합니다.

```http
GET /api/metrics/gold-sinks?hours=24
```

`hours`는 `1 / 24 / 168 / 720 / 4320 / 8760`이며 기본값은 `24`입니다. 잘못된 값은 HTTP 400, DB 오류는 HTTP 503이고 성공·DB 오류 응답은 `Cache-Control: no-store`입니다. 응답은 `from`, `until`, `collection_started_at`, `total_gold`, `entries`입니다. 각 행은 `{ sink, name, quantity, gold }`이며 `sink`는 `item_purchase / item_buyback / stall_tax / land_tax / land_recovery`입니다. 구매·재매입에만 `item_def_id`를 포함하고 이름은 현재 아이템 정의, 정의가 없으면 ID를 사용합니다. 금액은 코퍼 단위이며 총액은 모든 행의 합계입니다. 계정·캐릭터 정보는 반환하지 않습니다.

조회 범위는 정각으로 내린 현재 시각 `until`과 `from = until - hours × 3600`의 `[from, until)`입니다. 완료된 시간대만 표시하고 기록이 없으면 빈 목록과 0을 반환합니다. `gold_sink_samples`에 시간·항목·아이템별로 저장하고, `gold_sink_collection`의 수집 시작 시각은 재시작 후에도 유지합니다. 과거 기록을 소급 생성하지 않으며 수집 시작 전을 포함한 기간은 화면에 안내합니다.

구매·재매입·가판 수수료는 메모리에 합산해 다음 정각에 저장합니다. 저장 실패 시 복원해 재시도하며 로그아웃 후에도 유지하고 정상 종료 시 진행 중인 시간대도 저장합니다. 비정상 종료 시 미저장 통계는 유실될 수 있습니다. 토지세·복구 비용은 실제 차감과 같은 DB 트랜잭션에 저장합니다. 밀린 토지세도 실제 징수한 시각에 기록하며 같은 납부를 재집계하지 않습니다.

## 골드 상위 10명

레벨 순위 아래에 현재 골드 상위 10명 표와 해당 캐릭터들의 골드 변화 그래프를 좌우로 배치합니다. 오프라인을 포함한 전체 캐릭터에서 공식 NPC 계정(`npc_` 접두사)을 제외하고, 보유 골드 내림차순·동점이면 캐릭터 ID 오름차순으로 정렬합니다. 계정당 여러 캐릭터가 각각 진입할 수 있으며 같은 계정 표시는 레벨 순위와 같습니다. 골드가 0인 캐릭터도 순위 대상입니다.

```http
GET /api/metrics/gold-leaderboard?hours=168
```

조회 기간·구간 간격·응답 상태·캐시 정책은 레벨 순위 API와 같습니다. 순위와 이력은 같은 읽기 트랜잭션에서 조회합니다. `entries`는 `[{ "name": "모험가", "gold": 50000, "account_first_rank": 1 }]`, `series`는 `[{ "name": "모험가", "started_at": 1700000000, "samples": [{ "timestamp": 1700000000, "gold": 50000 }] }]` 형식이며 계정 이름과 캐릭터 ID는 노출하지 않습니다.

`character_gold_history`는 캐릭터 ID·수집 시각·보유 골드를 저장합니다. 최초 적용과 캐릭터 생성 시 기준값을 기록하고, 이후 시간별 작업에서 직전 관측값과 달라진 골드만 추가합니다. 같은 시간 안의 증가·감소는 생략되며 32초 게임 저장은 이력을 추가하지 않습니다. 순위 밖 캐릭터도 기록하고 이름 변경·재시작에도 유지하며 캐릭터 삭제 시 함께 삭제합니다. 기존 이력은 보존하고 과거를 소급 생성하지 않습니다.

그래프는 레벨 이력과 같은 방식으로 기간 시작의 기준점·최초 기록·각 구간 마지막 변경값을 계단선으로 연결합니다. 구간 내 중간 증가·감소는 생략될 수 있으며 수집 시작 이전은 비워 둡니다. 표와 범례에서 선택한 캐릭터를 강조하며 툴팁에는 정확한 금액을 `8g61s34c`처럼 표시합니다. 좁은 화면에서는 세로로 배치합니다. 레벨 그래프와 조회 기간·선택 캐릭터는 독립적이며, 1시간 갱신과 수동 새로고침은 저장된 데이터만 읽습니다.

## 무기 인챈트 상위 10명

골드 순위 아래에 같은 형식의 표와 변화 그래프를 표시합니다. 가방과 장비 슬롯에 보유한 무기 중 가장 높은 인챈트 단계를 캐릭터별로 계산합니다. 아이템 정의의 `weapon` 분류를 사용하므로 방어구·낚싯대 등은 제외하며, 장착 여부는 순위에 영향을 주지 않습니다. 창고나 바닥에 있는 아이템은 포함하지 않고, 보유 무기가 없으면 `+0`으로 표시합니다.

공식 NPC 계정을 제외한 전체 캐릭터를 최고 인챈트 내림차순·동점이면 캐릭터 ID 오름차순으로 정렬합니다. 계정별 중복 제거 없이 최대 10명을 표시하며 같은 계정의 캐릭터 표시는 레벨·골드와 같습니다. 표·그래프 축·툴팁은 `+7`처럼 표시합니다. 조회 기간과 선택 캐릭터는 다른 순위와 독립적입니다.

```http
GET /api/metrics/weapon-enchant-leaderboard?hours=168
```

지원 기간·구간 간격·응답 상태·캐시 정책은 레벨·골드 순위와 같습니다. `entries`는 `[{ "name": "모험가", "weapon_enchant": 7, "account_first_rank": 1 }]`, `series`는 `[{ "name": "모험가", "started_at": 1700000000, "samples": [{ "timestamp": 1700000000, "weapon_enchant": 7 }] }]` 형식입니다. 순위와 이력은 같은 읽기 트랜잭션에서 조회하며 계정 이름과 캐릭터 ID는 반환하지 않습니다.

`characters.weapon_enchant`는 저장된 인벤토리의 최고 무기 인챈트 값입니다. 최초 적용 시 기존 인벤토리에서 계산하고, 서버 시작 시 저장된 아이템과 맞춥니다. 이후 정기 저장·로그아웃·거래 등에서 인벤토리 교체가 끝난 뒤 같은 트랜잭션에서 갱신합니다. 아이템 행의 삭제·재삽입 도중 발생하는 임시 빈 인벤토리는 기록하지 않습니다.

최초 현재값과 이후 시간별로 관측한 최고값 변화를 `character_weapon_enchant_history`에 기록합니다. 동일한 최고값은 기록을 늘리지 않습니다. 무기 획득·강화·파괴·판매에 따른 변화도 다음 시간별 관측에 반영되며 중간 변화는 생략될 수 있습니다. 이름 변경·재시작 후에도 유지하고 캐릭터 삭제 시 함께 삭제합니다. 기존 이력은 보존합니다.

그래프는 다른 순위와 같은 계단선으로 기간 시작 기준점·최초 기록·구간별 마지막 변경값을 연결합니다. 1시간 갱신과 수동 새로고침은 저장된 값만 조회합니다.

## 방어구 인챈트 상위 10명

공식 NPC를 제외한 전체 캐릭터를 합계 내림차순·동점이면 캐릭터 ID 오름차순으로 정렬합니다. 최대 10명을 표시하며 같은 계정 표시, 표와 그래프의 색상·선택 강조, 독립적인 기간 선택, 1시간 자동 갱신은 무기 순위와 같습니다. 표·그래프 축·툴팁은 합계를 `+27`처럼 표시하며 보유 방어구가 없으면 `+0`입니다.

## 영지 보유 상위 10명

방어구 순위 아래에 캐릭터별 영지 보유 순위와 보유량 변화 그래프를 표시합니다. 개척지·왕령 등급을 모두 포함해 `land_estates.owner_id`별로 실제 `land_plots` 행 수를 합산합니다. 영지 개수나 세금 예치금이 아닌 필지 수 기준이며, 세금 연체 여부와 접속 여부는 집계에 영향을 주지 않습니다. 공식 NPC 계정(`npc_` 접두사)과 보유 필지가 없는 캐릭터는 제외합니다. 필지 수 내림차순·동점이면 캐릭터 ID 오름차순으로 최대 10명을 반환하며, 같은 계정의 캐릭터 표시는 기존 순위와 같습니다.

```http
GET /api/metrics/land-leaderboard?hours=168
```

지원 기간은 `168 / 720 / 4320 / 8760`시간(기본 168)이며 그래프 간격은 각각 `3600 / 3600 / 21600 / 86400`초입니다. 잘못된 기간은 HTTP 400, DB 조회 실패는 HTTP 503이며 성공·DB 오류 응답에 `Cache-Control: no-store`를 지정합니다. 응답은 `timestamp`, `from`, `sample_interval_seconds`, `entries`, `series`를 포함합니다. `entries`는 `[{ "name": "모험가", "land_plots": 16, "account_first_rank": 1 }]`, `series`는 `[{ "name": "모험가", "started_at": 1700000000, "samples": [{ "timestamp": 1700000000, "land_plots": 16 }] }]` 형식입니다. 현재 순위와 저장된 이력은 같은 읽기 트랜잭션에서 조회하며, 계정 이름·캐릭터 ID·필지 위치는 반환하지 않습니다.

`character_land_plots_history`에 최초 적용 시 기존 보유량을 기록하고, 새 캐릭터는 0필지에서 시작합니다. 이후 기존 순위 지표의 시간별 수집 작업에서 실제 소유 필지를 다시 집계해 직전 기록과 달라진 값만 추가합니다. 순위 밖 캐릭터도 수집하고 소유권 이전·필지 삭제에 따른 감소와 0필지도 저장합니다. 같은 시간 사이의 중간 변화는 생략될 수 있으며 현재 순위와 마지막 시간별 관측값은 다를 수 있습니다. 이름 변경·재시작 후에도 이력을 유지하고 캐릭터 삭제 시 함께 삭제합니다. 적용 이전의 보유량은 소급 생성하지 않으며 조회는 이력을 추가하지 않습니다.

그래프는 현재 상위 10명의 시간별 보유량을 계단선으로 연결합니다. 기간 시작 기준점과 각 표시 구간의 마지막 변경값을 사용하며, 최초 기록 이전은 비워 둡니다. 표와 툴팁은 `16 필지`처럼 표시하고, 캐릭터명·범례 선택으로 해당 선을 강조합니다. 1주일·1개월·6개월·1년 기간을 독립적으로 선택하며 1시간 자동 갱신과 수동 새로고침을 지원합니다.
