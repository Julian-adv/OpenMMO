# 운영 지표

## 동시 접속 계정 수

- 로그인한 뒤 게임에 입장했고, 현재 세션과 플레이어가 모두 남아 있는 계정을 셉니다. 로그인·캐릭터 선택 화면의 계정은 제외합니다.
- 계정당 하나인 서버의 현재 세션을 기준으로 하므로 중복 로그인을 두 번 세지 않습니다.
- `is_official_npc`인 공식 NPC는 제외합니다. 일반 플레이어의 외부 에이전트 접속은 포함하며 사람/봇을 추정해 분류하지 않습니다.
- 접속 핸드셰이크의 `ClientKind::Web`은 웹 접속(초록), `Cli`는 외부 에이전트(보라), `Other`·`Unknown`은 기타·미분류(회색)로 표시합니다. 클라이언트가 보고한 프로그램 종류 기준이며 실제 조작자가 사람인지 AI인지는 판별하지 않습니다.
- 현재 접속 카드와 그래프 툴팁은 합계 및 유형별 계정 수·비율을 표시합니다. 그래프는 유형별 누적 영역과 합계 선으로 표시하며, 기간 최고·평균 카드의 합계 계산은 유지합니다.
- 접속 종료가 서버에 반영되면 제외합니다. 네트워크 단절을 감지하기 전에는 세션이 잠시 집계에 남을 수 있습니다.
- `current`는 API 요청 시점의 접속 수입니다. 그래프와 기간 최고·평균은 1분 간격 관측값이므로 짧은 접속 증가가 최고값에 잡히지 않을 수 있습니다.

이 지표는 일정 기간 동안 접속한 서로 다른 계정 수인 DAU/WAU/MAU와 다릅니다. 최고·평균은 선택한 최근 1·6·24시간, 1주일, 1개월, 6개월, 1년 안에서 실제로 수집한 1분 표본만 사용합니다. 1개월·6개월·1년은 각각 최근 30일·180일·365일입니다. 기록이 없으면 최고·평균을 `—`로 표시하고, 실제 0명인 표본은 `0`으로 표시합니다.

## 수집과 저장

게임 서버가 REST API를 연 뒤 즉시 한 번, 이후 60초마다 접속 수를 읽어 기존 계정 SQLite DB의 `concurrent_account_samples`에 저장합니다. 표의 기본 키는 관측 시각을 분 단위로 내린 Unix 초입니다. 같은 분에 서버가 재시작하면 해당 분의 마지막 관측값으로 갱신합니다.

스키마는 `AuthService` 초기화에서 자동 생성되고 기존 계정·캐릭터 데이터를 변경하지 않습니다. 서버 재시작 후에도 기록이 유지됩니다. 현재는 기록을 자동 삭제하지 않으며, 하루 최대 1,440행입니다.

`web_accounts`와 `agent_accounts` 열은 자동 추가되며, 이전 합계 기록은 두 열이 `0`인 채 보존됩니다. 기타·미분류는 `accounts - web_accounts - agent_accounts`입니다. 과거 비율을 추정해 채우지 않으며, 새 서버에서 수집하는 기록부터 유형별 구성이 저장됩니다.

수집을 도입하기 전이나 서버가 꺼져 있었던 구간에는 표본이 없습니다. 수집 실패도 0으로 기록하지 않습니다. 대시보드는 표본이 없는 표시 구간에서 선을 끊습니다. 긴 기간은 구간 내 실제 표본의 평균을 그리므로 같은 구간 안의 짧은 수집 중단은 선에 나타나지 않습니다. 기존 접속 로그로 과거 수치를 역산하거나 채워 넣지 않습니다.

## API

```http
GET /api/metrics/concurrent?hours=24
```

`hours`는 아래 값을 지원하며 생략 시 `24`입니다. 나머지 값은 HTTP 400입니다. 기존 REST 포트(기본 10007)에서 제공하는 공개 읽기 API이며 계정 이름이나 캐릭터 식별자를 반환하지 않습니다. 저장소 조회 실패는 HTTP 503으로 응답합니다. 성공 및 저장소 오류 응답에는 `Cache-Control: no-store`를 지정합니다.

| 조회 기간 | hours | 그래프 간격 |
| --- | ---: | --- |
| 1시간 / 6시간 / 24시간 | 1 / 6 / 24 | 1분 |
| 1주일 | 168 | 10분 평균 |
| 1개월 (30일) | 720 | 1시간 평균 |
| 6개월 (180일) | 4320 | 6시간 평균 |
| 1년 (365일) | 8760 | 1일 평균 |

`sample_interval_seconds`는 그래프 집계 간격입니다. 구간은 Unix 초 기준으로 정렬하며, 첫 구간의 시작이 조회 범위보다 앞서면 `from`으로 표시합니다. 각 구간의 `accounts`는 실제 표본의 평균, `sample_count`는 표본 수, `peak_accounts`와 `peak_timestamp`는 원본 최고값과 최초 관측 시각입니다. 기간 평균은 표본 수로 가중 계산하며, 최고값과 기록 수 역시 원본 기준으로 유지합니다. 1년의 525,600개 분 기록은 약 365개 그래프 지점으로 반환합니다.

`current`와 `samples`는 `web_accounts`, `agent_accounts`, `other_accounts`를 포함하며 세 값의 합은 `accounts`입니다. 장기 구간은 모든 유형을 같은 표본 수로 평균하므로, 분류 전후 기록이 섞인 구간도 합계가 보존됩니다. 비율은 구간별 유형 평균을 구간 합계 평균으로 나눈 값입니다. 접속 합계가 `0`이면 모든 비율을 `0%`로 표시합니다.

응답 예시:

```json
{
  "from": 1699913600,
  "until": 1700000000,
  "sample_interval_seconds": 60,
  "current": { "timestamp": 1700000000, "accounts": 12, "web_accounts": 8, "agent_accounts": 4, "other_accounts": 0 },
  "samples": [
    { "timestamp": 1699999860, "accounts": 10, "web_accounts": 7, "agent_accounts": 3, "other_accounts": 0, "peak_accounts": 10, "peak_timestamp": 1699999860, "sample_count": 1 },
    { "timestamp": 1699999920, "accounts": 12, "web_accounts": 8, "agent_accounts": 4, "other_accounts": 0, "peak_accounts": 12, "peak_timestamp": 1699999920, "sample_count": 1 },
    { "timestamp": 1699999980, "accounts": 11, "web_accounts": 7, "agent_accounts": 4, "other_accounts": 0, "peak_accounts": 11, "peak_timestamp": 1699999980, "sample_count": 1 }
  ]
}
```

시간은 모두 UTC Unix 초입니다. `samples`는 `[from, until]` 범위의 기록을 시간 오름차순으로 반환합니다. 대시보드는 한국 시간(`Asia/Seoul`, KST)으로 표시하고 30초마다 갱신합니다. 네트워크 오류 시 마지막 수신 시각과 갱신 중단 상태를 표시하며, 이전 값을 현재 값인 것처럼 표시하지 않습니다.

## 유니크 접속 계정 추이

동시 접속 추이 아래에 일별 유니크 계정 그래프를 표시합니다. 매일 한국 시간 자정 기준으로 직전 1일·7일·30일·180일·365일 동안 게임에 머문 서로 다른 계정 수를 각각 집계합니다. 기간 선택은 1일, 1주일, 1개월, 6개월, 1년이며 1시간·6시간은 지원하지 않습니다. 화면에는 마지막 집계 기준 시각을 표시합니다.

계정 이름을 정규화해 재접속과 캐릭터 변경을 중복 제거하고 공식 NPC는 제외합니다. 해당 기간 전에 입장해 기간 안까지 접속을 유지한 계정도 포함합니다. 날짜별 숫자를 더하지 않고 각 기간의 계정을 한 번씩 세므로, 여러 날 접속한 계정도 한 계정입니다. 각 자정 `t`의 집계 범위는 `[t - 선택 기간, t)`이며 자정에 새로 입장한 계정은 다음 집계에 포함합니다.

게임 입장과 종료 시 `account_activity_sessions`에 접속 구간을 저장하고, 접속 중에는 60초마다 마지막 확인 시각을 갱신합니다. 정상 종료 시 마지막 스냅샷도 저장합니다. 서버가 비정상 종료되면 마지막으로 저장한 시각까지만 접속한 것으로 처리합니다. 기록 실패는 서버 로그에 남으며, 저장되지 않은 접속은 집계에서 빠질 수 있습니다.

1분 주기 수집 작업에서 자정이 지난 뒤 처음 한 번 계정별 마지막 접속 시각을 읽어 다섯 기간의 값을 계산합니다. 결과는 `unique_account_daily_samples`에 날짜당 한 행으로 저장합니다. 이미 저장된 날짜는 재계산하지 않으며, 날짜별 집계와 저장은 한 트랜잭션으로 처리합니다. 실패하면 다음 수집 작업에서 다시 시도합니다.

서버 시작 시 게임·API 접속을 받기 전에 수집 시작 이후부터 가장 최근 한국 시간 자정까지 누락된 모든 날짜를 오래된 순서로 집계합니다. 기존 기록 사이에 빠진 날짜도 채우며, 이미 저장된 결과는 유지합니다. 서버가 며칠 꺼져 있었더라도 각 자정 기준의 접속 이력으로 다섯 기간을 각각 계산합니다. 서버 중단 기간에 새 접속이 없어도 주간·월간 집계에는 그 전에 접속한 계정이 포함될 수 있습니다. 보충 집계에 실패하면 오류를 기록하고 시작을 중단하며, 다음 시작 시 완료된 날짜는 건너뛰고 나머지를 처리합니다.

`unique_account_collection`의 최초 수집 시작 시각을 유지합니다. 첫 집계는 수집 시작 이후 처음 맞는 한국 시간 자정에 생성합니다. 이전 동시 접속 합계로 과거 이력을 추정하지 않으며, 선택 기간 전체의 이력이 없으면 화면과 툴팁에서 알립니다. 첫 집계 전에는 대기 상태, 집계된 날짜에 접속이 없으면 `0`, 집계하지 못한 날짜는 빈 구간으로 표시합니다. 기존 접속 이력과 집계 결과는 현재 자동 삭제하지 않습니다.

```http
GET /api/metrics/unique?hours=24
```

지원하는 `hours`는 `24 / 168 / 720 / 4320 / 8760`이며 기본값은 `24`입니다. 잘못된 기간은 HTTP 400, DB 조회 실패는 HTTP 503입니다. 성공·DB 오류 응답에는 `Cache-Control: no-store`를 지정합니다.

응답은 `from`, `until`, `window_seconds`, `sample_interval_seconds`, `collection_started_at`, `last_aggregated_at`, `samples`를 포함합니다. `until`은 요청일의 한국 시간 자정이고 `from`은 선택 기간만큼 앞선 자정입니다. `sample_interval_seconds`는 항상 `86400`이며, `last_aggregated_at`은 가장 최근 저장된 집계의 기준 시각입니다. 첫 집계 전에는 `null`입니다.

각 표본은 `{ "timestamp": 1700002800, "accounts": 12 }` 형식이며 계정 식별자는 공개하지 않습니다. 최대 표본 수는 선택 일수 + 1개입니다. 그래프 요청은 저장된 일별 숫자만 읽으며 접속 이력 조회나 중복 제거 계산을 실행하지 않습니다. 대시보드의 30초 갱신과 새로고침도 일별 집계를 다시 실행하지 않습니다.

앱 실행과 독립 정적 배포 방법은 [dashboard/README.md](../dashboard/README.md)에 있습니다.
