# 아이템 잠금과 바닥 이동 로그

기본 상태에서는 잠긴 아이템에만 노란 자물쇠를 표시한다. 가방의 **Select** 옆 **Lock** 버튼을 누르면 가방과 장비창의 모든 아이템에 자물쇠 버튼이 나타나 새로 잠글 수 있다. **Lock**을 다시 누르거나 **Select**를 누르거나 가방을 닫으면 잠긴 아이템의 표시만 남긴다. **잠금 해제는 Lock 모드와 관계없이 노란 자물쇠를 눌러 진행할 수 있다.** 잠금 상태는 툴팁에서도 확인할 수 있다.

자물쇠 버튼을 한 번 누르면 잠긴다. 노란 자물쇠가 잠금 상태다. 같은 종류의 아이템을 여러 개 가지고 있어도 선택한 아이템 또는 표시된 묶음만 잠긴다. **Lock**을 켜면 기존 일괄 버리기 선택은 해제된다.

잠금을 해제하려면 자물쇠를 누른 뒤, 아이템 이름·강화 수치·수량을 확인하고 `UNLOCK`을 대문자로 정확히 입력해 **Unlock**을 누른다. 취소 또는 Esc로 닫으면 잠금을 유지하며, 다시 열 때는 확인 문구를 새로 입력해야 한다. 확인 중 해당 칸의 아이템이 바뀌면 확인창을 닫는다.

## 잠금 범위

- 단일·일괄 버리기, 상점 판매, 개인 거래, 노점 판매를 서버에서 거절한다. 일괄 요청에 잠금 아이템이 하나라도 있으면 전체 요청을 거절한다.
- 잠긴 무기는 강화할 수 없고, 잠긴 방어구는 무작위 강화 대상에서 제외한다. 강화 가능한 대상이 없으면 주문서와 연마유를 소모하지 않는다.
- 장착·해제와 일반 사용은 허용한다. 주문서·연마유 자체의 잠금은 사용을 막지 않는다.
- 보관함에 넣고 꺼낼 수 있으며 잠금도 함께 보존된다.
- 거래에 제시했거나 노점에 진열한 아이템은 먼저 회수해야 잠금을 변경할 수 있다. 거래·노점 판매의 최종 처리 시점에도 잠금을 다시 검사한다.
- 재접속 후에도 잠금이 유지된다. 기존 아이템은 잠금 해제 상태로 시작한다.

`ItemInstance.locked`는 `character_items.locked`, `estate_chest_items.locked`에 저장된다. 잠금 상태가 다른 스택은 합쳐지지 않는다. 메시지 `SetItemLocked { instance_id, locked }`는 본인이 소유한 가방·장비 아이템에만 적용된다. 프로토콜 버전은 69이며 배포 시 원격 agent-client도 함께 갱신해야 한다.

## 바닥 이동 기록

일반 아이템의 성공한 단일·일괄 드롭과 줍기를 `item_audit` INFO 로그로 남긴다. 실패한 요청은 이동 기록을 남기지 않는다. 코인 더미는 기존 획득 금액 로그를 유지한다.

| 필드 | 의미 |
| --- | --- |
| `action` | `drop` 또는 `pickup` |
| `character_id`, `player_id`, `name` | 캐릭터 DB ID, 접속 중 플레이어 ID, 이름 |
| `ground_instance_id` | 바닥에 놓인 아이템 ID |
| `bag_instance_id` | 드롭 전 소유 아이템 ID 또는 줍기 후 가방 ID |
| `item_def_id`, `enchant`, `quantity` | 아이템 종류, 강화 수치, 실제 이동 수량 |
| `x`, `y`, `z`, `floor` | 바닥 아이템 위치와 층 |
| `dropped_by` | 직접 버린 플레이어 ID; 몬스터 전리품 등은 없음 |

줍기가 기존 스택에 합쳐지면 실제 합쳐진 스택 ID를 기록한다. 일괄 드롭은 각 바닥 더미마다 기록한다. 바닥 ID를 따라 드롭과 줍기를 연결할 수 있지만, 인스턴스 ID는 재접속·재시작을 넘는 영구 식별자가 아니다. 바닥 소멸과 서버 재시작은 이 로그의 추적 범위에 포함하지 않는다.
