# 구호소 부활

상태: 구현됨 (2026-11-27, 프로토콜 185), 미배포. 영지 수호전([ESTATE_DEFENSE.md](ESTATE_DEFENSE.md)) 논의 중 나온 아이디어.

영지 주인이 영지에 **구호 침상**(가칭)을 놓으면 그 영지가 구호소가 된다. 죽은 사람은 부활 대화상자에서 어디서 깨어날지 고른다. 마을 여관 병실, 자기 영지, 본가, 그리고 주인이 공개한 가까운 구호소 중에서 고른다. 공개 구호소는 근처에서 죽은 누구나 쓸 수 있다.

관련 문서: [영지](LAND_SYSTEM.md), [영지 보관함·가구](ESTATE_STORAGE.md), [가문](FAMILY_SYSTEM.md), [영지 수호전](ESTATE_DEFENSE.md).

## 지금 동작

- 사망 시점에 경험치 페널티가 붙는다(`combat.rs` `on_player_died`). 부활은 그 뒤 일이라 어디서 깨어나든 페널티는 같다.
- 부활 대화상자(`RespawnDialog.svelte`)에는 `마을에서 부활`, `나중에`, 부활 부적이 있으면 부적 사용 버튼이 있다.
- `RequestRespawn`(인자 없음)을 받으면 서버가 여관 병실의 빈 침대(`world.json`의 `respawn.bedIds`)에 눕힌다. 빈 침대가 없으면 병실 지정 위치에 세운다. 코콜리·미리엘 같은 메이드에게 알림이 간다.
- 영지 귀환 주문서(800c)는 즉시 이동이고 던전·전투 중에도 쓸 수 있다. 귀향의 깔개가 있으면 그 위로 간다(`estate_return.rs`).
- 영지에 놓은 Bed·Rustic Bed(ORKEA, 각 4,000c)에는 이미 누울 수 있고, 16초 쉬면 HP·MP 회복이 2배다(`bed_rest.rs`).
- 던전 안 좌표는 입구 근처 x·z를 쓴다(`dungeon_defs::dungeon_at`). 던전에서 죽어도 사망 지점과 구호소의 거리를 같은 방식으로 잴 수 있다.

## 이 기능이 주는 것

**영지 주인에게.** 던전까지 걷는 길이 짧아진다. 영지는 보통 마을보다 던전에 가깝고, 개척지는 던전 입구에서 150m(왕령 고리 바깥)만 떨어져 있으면 살 수 있다. 다만 지금도 여관에서 일어나 영지 귀환 주문서를 읽으면 몇 초 안에 영지로 간다. 지금과 비교해 실제로 달라지는 것은 "죽은 뒤 전진 기지로 가는 일이 공짜가 되고 한 번에 된다"는 점이다.

**다른 사람에게.** 이쪽이 새로운 부분이다. 영지가 없는 사람, 주문서 목적지가 아닌 곳에서 죽은 사람이 근처 공개 구호소에서 깨어난다. 사냥터 가까운 영지가 길가 여관 역할을 한다. 영지가 마을 밖 생활권이 되는 [영지 문서](LAND_SYSTEM.md)의 목표와 맞는다.

## 구호 침상

- ORKEA 가구로 판다(`furniture_aid_cot`, 8,000c). 전시품은 매장 2층 165번이다(`data/furniture_shop.json`). 다른 가구와 같은 배치·이동·회수 경로(`estate_chests`, `estate_storage.csv`)를 쓴다. 모델은 기존 Rustic Bed(`rustic_bed.glb`)의 담요 색만 바꾼 변형이다(예: 흰 담요에 붉은 줄). 새 형태를 만들지 않고 텍스처만 바꿔 별도 GLB·아이콘으로 낸다. 적십자 모양은 쓰지 않는다(국제 보호 표장이라 게임에서 쓰면 안 된다).
- 부활 지점이 되는 것은 구호 침상뿐이다(결정 2026-11-26). 일반 침대(Bed·Rustic Bed)는 지금처럼 눕기와 회복 2배만 한다. 어느 가구가 부활 지점인지 헷갈리지 않고, 공개 설정을 둘 곳이 하나로 정해진다.
- 구호 침상에서도 눕기와 회복 2배는 일반 침대와 같다.
- 한 영지에 여러 개 놓을 수 있다. 공개 설정은 영지 단위로 하나다(침상마다 따로 두지 않는다).

### 공개 설정

영지 주인(같은 계정의 캐릭터)이 구호 침상을 우클릭하면 나오는 메뉴(내 영지만 / 가문원까지 / 근처의 누구나)에서 고른다. 지금 설정에 ✓가 붙는다. `Estate Editor → Objects → Select`로 침상을 골라도 같은 버튼이 나온다. 그 영지의 모든 구호 침상에 함께 적용된다.

| 설정 | 깨어날 수 있는 사람 |
| --- | --- |
| 영지 | 그 영지 계정의 캐릭터 |
| 가문 | 위 + 그 영지가 본가인 가문의 가문원. 본가가 아닌 가문 영지는 `영지`와 같다 |
| 공개 | 누구나. 다만 아래 "가까운 구호소" 조건 안에서 |

기본값은 `영지`. 가문원에게 제안하는 것은 본가 하나뿐이라, 본가가 아닌 영지에서 `가문`은 `영지`와 같다.

## 부활 대화상자

| 버튼 | 보이는 조건 |
| --- | --- |
| 부활 부적 사용 | 지금과 같음 |
| 마을에서 부활 | 항상 |
| 내 영지에서 부활 | 내 계정 영지에 안전한 구호 침상이 있을 때. 거리 무관 |
| 본가에서 부활 | 가문원이고, 본가가 `가문` 이상으로 열려 있고, 안전한 침상이 있을 때. 거리 무관 |
| 가까운 구호소에서 부활 | 사망 지점에서 여관보다 가까운 공개 구호소가 있을 때. 그중 가장 가까운 곳 하나. 영지 이름(또는 주인 이름)과 거리를 함께 보인다. 무료 |
| 나중에 | 지금과 같음 |

- 자기 영지와 본가는 주문서로 갈 수 있는 곳이라 거리 제한을 두지 않는다. 공개 구호소는 "여관보다 가까운 곳"만 보여 준다. 그래서 반경 수치를 따로 정할 필요가 없고, 멀리 있는 공개 구호소가 공짜 장거리 이동 수단이 되지 않는다.
- 가까운 구호소는 하나만 보여 준다. 고를 목록을 길게 만들지 않는다.
- 기본 강조 버튼은 지금처럼 `마을에서 부활`.

## 침상 고르기와 도착

- 그 영지의 침상을 먼저 설치한 순서로 살펴, 안전하고 비어 있는 첫 침상에 눕는다. 모두 차 있으면 영지 귀환 주문서가 도착하는 영지의 안전한 바깥 땅에 선다. 그런 땅이 없으면 첫 침상 자리에 선다.
- "안전한 침상"은 지금 그 영지가 소유한 구획 위에 있고, 바닥이 남아 있는(실내 0~3층은 통행 캐시의 그 층 바닥, 바깥은 수심 0.1m 이하 지면) 침상이다. 침상 자체가 막힌 칸이라 막힘 검사는 하지 않는다.
- 누운 상태는 영지 침대에 직접 누운 것과 같다(`object_type` = 침상 아이템 ID, `object_id` = `estate_chests.id`).
- 버튼을 누른 사이 침상을 회수했거나, 설정을 닫았거나, 영지가 압류되어 갈 곳이 없어지면 마을에서 깨어나고 이유를 시스템 메시지로 알린다.
- HP는 최대치, 허기 초기화, 마나 회복 지연 등은 여관 부활과 같다.

## 규칙

### 체납

체납(`missed > 0`) 영지의 구호소는 주인 본인 외에는 쓸 수 없다. 주인 본인은 영지 귀환 주문서처럼 체납이어도 막지 않는다. 가문원·공개 이용은 가문 귀환 주문서처럼 막는다.

### 던전·필드 레이드

막지 않는다. 주문서가 던전에서도 쓰이므로 자기 영지 부활을 막아도 800c만 되살아난다. 던전 가까운 영지가 전진 기지가 되는 것은 이 기능의 목적에 가깝다. 사망 비용의 대부분은 경험치 페널티(레벨 구간 15%)라 800c 차이는 작다. 공개 구호소는 던전 입구 근처 영지에 몰릴 것이다.

### 영지 수호전 중

막지 않는다(결정 2026-11-26). 구호 침상을 놓는 이유 중 하나가 수호전에서 죽은 사람이 바로 돌아와 다시 싸우는 것이다. 막아도 주문서로 몇 초 안에 돌아오므로 얻는 것이 없다. 죽음의 비용은 사망 시점의 경험치 페널티(레벨 구간 15%)로 충분하다. 깨어난 침상에서 쉬면 회복 2배를 받으므로, 침상을 깃발 가까이 두는 것은 수호 준비의 일부가 된다. 다만 뿔나팔을 분 자리 반경 10m 안에 침상이 있으면 빈 터 조건에 걸려 불 수 없다.

### 깨어난 직후 보호

두지 않는다. 지금 여관 부활과 주문서 도착에도 보호 시간이 없다. 위험한 곳이면 마을을 고르면 된다. 깨어나자마자 다시 죽는 일이 보고되면 그때 짧은 보호를 넣는다.

### 남의 집에서 깨어나는 사람

- 공개 구호소가 집 안에 있으면 모르는 사람이 그 집에서 깨어난다. 보관함·가문 창고·게시판은 지금도 소유·가문 권한으로 검사하므로 열 수 없다. 걸어 다니는 것만 된다. 집에 문 잠금은 아직 없다(LAND_SYSTEM.md의 후속 항목).
- 울타리로 둘러싼 가둠 터에 공개 침상을 두는 장난이 가능하다. 마을 버튼이 항상 있고, 공개 구호소는 사람이 직접 고를 때만 가므로 피해는 한 번 나가는 수고다. 걸어서 영지 밖으로 나갈 수 있는지는 검사하지 않는다(경로 탐색 비용). 신고가 오면 운영자가 공개 설정을 끈다.

### 이용료

없다(결정 2026-11-26). 공개 구호소는 공공을 위한 봉사다. 남에게 열기 싫은 주인은 공개 범위를 `영지`나 `가문`으로 두면 된다. 사망이 누군가의 수입이 되지 않으므로 다계정으로 일부러 죽어 골드를 옮기는 경로도 없다.

## 지도 표시

공개(`공개` 설정) 구호소를 월드맵에 작은 표지로 보인다(결정 2026-11-26). 근처에서 죽을 사람이 미리 알 수 있고, 영지가 길가 쉼터처럼 보인다.

- 위치는 그 영지의 첫 안전한 침상 좌표. 마우스를 올리면 영지 이름(없으면 주인 이름)을 보인다.
- `영지`·`가문` 설정 구호소는 지도에 나오지 않는다. 가문원에게 본가 표지를 따로 보이는 것은 후속.
- 데이터는 공개 API `GET /api/terrain/shelters`(영지 소유 API와 같은 방식의 DB 조회 한 번)에서 받는다. 지도를 열 때 한 번 읽는다. 체납 영지는 빠진다.

## 경제

- 영지 귀환 주문서 소비가 일부 준다(죽은 뒤 영지로 가려고 읽던 몫). 규모는 prod 저널의 `consumed` 로그에서 사망 직후 주문서 사용을 세면 알 수 있다.
- 구호 침상 판매가 새 골드 회수처다. 값은 일반 침대(4,000c)보다 높게, 예를 들어 8,000c.

## 프로토콜과 클라이언트

- `ClientMessage::RequestRespawn`에 목적지를 붙인다: `RequestRespawn { place: RespawnPlace }`, `RespawnPlace = Town | Estate | FamilySeat | Nearby { estate_id }`. 프로토콜 번호를 올린다.
- 부활 대화상자가 열릴 때 클라이언트가 `RequestRespawnOptions`를 보내고, 서버가 `RespawnOptions { estate, family_seat, nearby: Option<NearbyShelter { estate_id, name, distance_m }> }`로 답한다. 대화상자는 이것으로 버튼을 정한다. `Nearby`는 서버가 사망 지점 기준으로 다시 찾아 같은 영지일 때만 받아 준다.
- 공개 설정은 `SetShelterAccess { furniture_id, access }`. 주인 계정만 바꿀 수 있고, 바뀌면 그 영지 구호 침상들의 `EstateChest.shelter`를 다시 보낸다.
- agent-client `{"type": "respawn"}`은 선택 인자 `at`(`estate`·`family`, 그 밖은 마을)을 받는다. MCP 안내문도 같이 고쳤다. NPC(공식 캐릭터)는 지금처럼 일정표 위치에서 일어난다.
- i18n: 버튼 문구, 공개 설정, 실패 메시지.

## 데이터

- `land_estates`에 `shelter_access INTEGER NOT NULL DEFAULT 0`(0 영지, 1 가문, 2 공개).
- 침상은 `estate_chests`의 `item_def_id = furniture_aid_cot` 행. 구호 침상의 `EstateChest.shelter`에 영지의 공개 설정을 싣는다.
- 서버 메모리 `EstateChestIndex`가 구호 침상 id 집합을 따로 둔다. 설치·회수 때 함께 바뀌고, 설정 변경은 `set_shelter`로 반영한다.

## 동접 5,000

- "여관보다 가까운 공개 구호소"는 메모리의 구호 침상 집합만 훑는다. 고른 영지(가까운 순 최대 3곳)만 DB로 공개·체납을 확인한다.
- 자기 영지·본가 확인은 대화상자를 열 때와 부활 때 DB 조회 한 번씩.
- 침상과 귀향의 깔개의 바닥 검사는 디스크의 집 파일 대신 메모리의 통행 캐시(`get_floor_y_base`)를 쓴다. 전에는 주문서를 읽을 때마다 `read_all_houses()`로 모든 집 파일을 읽었다.
- `respawn_player`는 조회와 검증을 `lock_player_movement` 전에 하고, 고른 침상 위치를 잠금 목적지에 넣는다.
- 빈 침상 판정은 다른 플레이어의 `object_type`과 `object_id`를 함께 본다. 여관 침대 ID와 `estate_chests.id`가 겹칠 수 있어서다.
