# 클래스 기본 스킬 설계 (Barbarian·Caveman·Valkyrie·Priest·Bard)

작성일: 2026-10-28. 광폭화는 프로토콜 v130, 야성의 포효는 v131, 발할라의 돌격은 v132로 구현했고(2026-10-29), 치유의 기도와 HP 공개 범위 변경은 v133, 전투의 찬가는 v134로 구현했다(2026-10-30).

플레이어가 고를 수 있는 8개 클래스 중 Knight(Guardian Ward)와 Rogue(Double Slash)만 공개된 클래스 스킬이 있다. Ranger의 True Aim은 구현돼 있지만 공개 결정 전까지 숨겨 두었으며, 이 문서에서는 다루지 않는다. 나머지 다섯 클래스에 기본 스킬을 하나씩 준다. 출발점은 [이슈 #198](https://github.com/Julian-adv/OpenMMO/issues/198)의 제안이며, 수치와 효과는 [전투 공식](../COMBAT.md)과 [마나 설계](../MANA_SKILLS_MAGIC.md)에 맞춰 다시 정했다.

## 1. 공통 규칙

- 클래스 기본 능력이므로 기존·신규 캐릭터 모두 습득 없이 쓴다. 운영 NPC도 같은 조건을 적용한다.
- 다섯 스킬 모두 시작 장비만으로 쓸 수 있다. Barbarian·Caveman·Valkyrie·Priest는 `worn_iron_sword`, Bard는 `worn_mandolin`을 받는다.
- 모든 클래스 스킬은 MP를 1 이상 쓴다. 물리 클래스(Barbarian·Caveman·Valkyrie)의 스킬은 전투 기술이며 MP 1, Priest·Bard 스킬은 마법이며 스킬별로 정한다.
- 즉시 발동한다. 시전 시간 처리와 갑옷 시전 배수는 아직 구현되지 않았으므로 Guardian Ward처럼 시전 시간 0으로 둔다. 전투의 찬가만 10초 연주가 시전 역할을 한다.
- 거절된 요청은 MP와 재사용 대기를 소비하지 않는다. 재사용 대기는 캐릭터별로 서버 메모리에 두고, 재접속으로 초기화되지 않는다.
- 사망·로그아웃 시 버프·디버프가 해제된다. 탑승·월드 로딩 중에는 쓸 수 없다.
- 에이전트는 `use_ability`로 쓴다. 이슈의 "HP 30% 이하일 때 발동" 같은 조건은 서버 규칙에 넣지 않으며, 사용 시점은 사람과 에이전트가 각자 판단한다.

### 처치 시간 기준

재사용 시간은 몬스터 한 마리를 잡는 데 걸리는 시간에 맞춘다. 2026-10-28에 prod 기록으로 측정했다.

| 레벨 | 근거 | 마리당 공격 | 마리당 교전 시간 |
| --- | --- | --- | --- |
| 50 | 감시 대상 Barbarian 2명의 공격 기록(10/25~10/28), 같은 몬스터 ID의 첫 공격~마지막 공격 | 중앙값 4~5회, 90% 5~7회 | 중앙값 6~8초, 90% 8~11초 |
| 1 | 공식 계산(시작 검 1d6, STR +3, 공격 간격 1.53초) | Kobold 2, Goblin 3, Orc 5 | 약 2.5초 / 4초 / 8초 |

- 50레벨이 주로 잡는 몬스터는 Skeleton Warrior(25)·Skeleton(17~20)·Cyclop(18~24)이다. 명중 보너스가 커서 거의 모두 맞히므로, 처치 시간은 몬스터 HP를 평균 피해로 나눈 값이 된다.
- 7일 처치 로그(약 125만 건)의 같은 플레이어 연속 처치 간격 중앙값은 1레벨 8.0초, 50레벨 10.8초다. 다음 몬스터까지 이동하는 시간이 포함돼 있다.
- 기준은 마리당 약 7~8초다. Double Slash(10초)는 마리당 약 1회 쓴다.

| 스킬 | 재사용 | 몬스터 기준 사용 빈도 |
| --- | ---: | --- |
| 광폭화 | 20초 (지속 10초) | 2마리마다 1회, 한 마리 동안 켜짐 |
| 야성의 포효 | 30초 | 약 4마리마다 1회 |
| 발할라의 돌격 | 10초 | 마리당 1회 |
| 치유의 기도 | 8초 | 마리당 약 1회 |

### 사용 로그

시전이 성공할 때마다 서버가 `ability_use` INFO 로그를 한 줄 남긴다: `ability cast name=<캐릭터> ability=<AbilityId> targets=<버프를 받은 인원, 단일 대상은 1> floor=<층>`. 스킬 사용 빈도를 journald에서 세는 용도다([이슈 #200](https://github.com/Julian-adv/OpenMMO/issues/200)). 거절된 요청은 남기지 않는다. 전투의 찬가는 연주가 끝나 효과가 걸릴 때, Radiance는 켤 때만 남긴다.

## 2. 광폭화 (Rage) — Barbarian

| 항목 | 규칙 |
| --- | --- |
| ID | `rage` |
| 분류 | 전투 기술, MP 1 |
| 장착 조건 | 주무기가 근접 무기(Sword·Great Sword·Axe·Mace·Club·Spear·Dagger). 방패 제한 없음 |
| 대상 | 자신 |
| 효과 | 근접 공격 피해 `+(3 + floor(Level / 10))`, Guard -2 |
| 지속·재사용 | 지속 10초, 재사용 20초 (가동률 50%) |
| 중첩 | 재사용 대기 중에는 다시 쓸 수 없으므로 중첩이 없다 |
| 해제 | 지속 종료·사망·로그아웃. 근접 무기를 해제하면 즉시 해제 |

10초는 몬스터 한 마리를 잡는 시간(1절)을 덮는다. 한 마리는 광폭화로 빨리 잡고 다음 한 마리는 평소대로 잡는 흐름으로, 2마리마다 한 번 쓴다.

피해 보너스는 무기 인챈트처럼 피해 합계에 더하고 치명타 2배에 포함한다. Double Slash의 각 타격처럼 한 번의 공격이 여러 타격이면 타격마다 더한다. Guard -2는 장비·Guardian Ward까지 반영한 최종 Guard에서 뺀다.

| 기준 | 평소 평균 피해 | 광폭화 보너스 | 증가율 |
| --- | ---: | ---: | ---: |
| 1레벨, `worn_iron_sword` 1d6, STR 18(+4) | 7.5 | +3 | +40% |
| 30레벨, `steel_longsword` 1d10, +5, STR 18 | 14.5 | +6 | +41% |
| 50레벨, `steel_longsword` 1d10, +7, STR 18 | 16.5 | +8 | +48% |

마리당 공격 횟수(폭발 d20·치명타 5% 포함 모의 계산, 공격 간격 1.53초):

| 기준 | 대상 | 평소 | 광폭화 |
| --- | --- | ---: | ---: |
| 1레벨, 1d6+3 | Goblin (HP 9, Guard 9) | 2.6회, 4.0초 | 1.9회, 2.9초 |
| 1레벨, 1d6+3 | Orc (HP 18, Guard 11) | 5.2회, 8.0초 | 3.7회, 5.7초 |
| 50레벨, 1d10+12 | Skeleton 19레벨 (HP 86, Guard 20) | 5.2회, 7.9초 | 3.8회, 5.9초 |
| 50레벨, 1d10+12 | Skeleton Warrior 25레벨 (HP 113, Guard 24) | 6.7회, 10.2초 | 4.8회, 7.3초 |

50레벨 Skeleton 5.2회는 실측 중앙값(4~5회)과 맞는다. 광폭화를 쓴 마리는 공격 1.4~1.9회, 2~3초 빨리 잡는다. 켜 있는 동안 피해 +40~48%, 가동률 50%라 평균 피해 증가는 약 +20~24%다. Double Slash(MP 0, 약 +12%)보다 크며, 차이는 MP 1과 Guard -2로 치른다.

### 구현 상태

- 서버: `AbilityId::Rage`. 버프는 `Abilities.rages`에 두고, `Abilities::guard`가 Guardian Ward 적용 뒤 2를 뺀다. 피해 보너스는 `resolve_player_attack`에서 광폭화 중인 모든 타격에 더한다. 광폭화는 근접 무기로만 시작하고, 장비가 바뀌어 `send_inventory_snapshot`이 나갈 때 근접 무기가 없으면 즉시 해제되기 때문이다.
- 웹: Barbarian **SKILLS**와 퀵슬롯, 버프 표시·툴팁, 5개 언어 문구. 아이콘은 Double Slash 스타일의 흑백 양손 도끼([`rage.png`](../../client/public/icons/skills/rage.png))다. 효과음은 없다.
- 지속 표시: 광폭화 중인 캐릭터 몸 둘레에 맥박처럼 뛰는 옅은 붉은 일렁임과 올라가는 붉은 불씨가 보인다. 발밑 원반은 기울어진 지형에 반쯤 묻혀서 뺐다. 시전자뿐 아니라 주변 플레이어에게도 보인다. 서버가 `Player.raging`과 `PlayerRageToggled`(주변 상태 전송)로 알린다. 일반 블렌딩이라 밝은 바닥에서도 주황으로 바뀌지 않는다. 화면 안의 광폭화 캐릭터를 인스턴스 메시 2개로 함께 그리며, 가까운 32명까지 표시한다([rage-aura.ts](../../client/src/lib/effects/rage-aura.ts)).
- agent-client: `{"type":"use_ability","ability":"rage"}`, Barbarian 세계 상태에 준비·MP·남은 시간 안내.

Guard -2의 대가는 레벨과 무관하게 받는 피해 약 +20~25%다. Guard 15·Orc(+4)는 명중률 45%→55%, Guard 40·Ogre(+8)는 2%→2.5%다.

### MP 1과 능력치

광폭화는 능력치와 연동하지 않는다. Barbarian은 클래스 보정이 INT -2, WIS -2(여성 -1)이고, prod 남성 Barbarian의 WIS 중앙값은 10이다. WIS·INT는 버리는 수치로 보고, 능력치 선택은 캐릭터 생성 때 STR·CON·DEX 중 무엇을 높게 받느냐로 남긴다. 능력치는 생성 때 굴리기만 하며 배분·성장이 없다.

WIS·INT로 광폭화 지속시간이나 피해를 늘리는 안도 검토했다. 50레벨에서는 WIS 빌드가 STR 빌드보다 약 10% 앞서게 만들 수 있었지만, Barbarian에서 WIS 14 이상은 생성 확률 10% 미만이라 사실상 다시 굴리기를 반복해야 하는 빌드였다. 설명이 복잡해지는 데 비해 얻는 것이 적어 넣지 않았다. MP 비용·지속시간·재사용만으로는 STR과 WIS의 가치를 맞출 수 없었다. WIS가 주는 MP는 레벨에 비례하는 저장량이고, STR은 매 공격에 붙기 때문이다.

연속 사냥 중에는 비전투 10초 조건을 채우지 못해 MP가 거의 회복되지 않는다.

| 기준 (WIS 10~11) | 최대 MP | 연속 광폭화 | 그동안 잡는 수 (2마리당 1회) | MP 완충 휴식 |
| --- | ---: | ---: | ---: | ---: |
| 1레벨 | 15 | 15회 | 약 30마리, 약 5분 | 16초당 1, 약 4분 |
| 50레벨 | 82 | 82회 | 약 160마리, 약 27분 | 16초당 7, 약 3분 (침대 약 1.5분) |

1레벨은 5분쯤 쓰면 바닥나므로 쉬는 시점을 고르게 된다. 50레벨은 한 번 사냥에 충분하다. Guardian Ward는 MP 2로 45초마다 다시 걸어 분당 약 2.7을 쓰고, 광폭화는 계속 쓰면 분당 3을 쓴다.

## 3. 야성의 포효 (Primal Roar) — Caveman

| 항목 | 규칙 |
| --- | --- |
| ID | `primal_roar` |
| 분류 | 전투 기술, MP 1 |
| 장착 조건 | 없음. 맨손도 가능 |
| 범위 | 같은 층, 시전자 반경 4m, 벽 너머는 제외 |
| 시전 | 포효 동작 동안 1.85초간 시전자의 자동 공격을 미룬다. 임시 HP는 시전 즉시 받는다 |
| 효과 1 | 시전 1.05초 뒤 발 구르기 시점에 범위 안의 살아 있는 몬스터를 3.7초 경직시킨다 |
| 효과 2 | 시전자에게 임시 HP `max(4, floor(최대 HP × 15%))`를 10초간 준다 |
| 재사용 | 30초. 처음엔 45초였으나 시전 중 공격이 1.85초 멈추게 되면서 줄였다 |
| 아이콘 | 포효하는 얼굴([`primal-roar.png`](../../client/public/icons/skills/primal-roar.png)) |

경직은 몬스터 행동 트리의 기존 피격 경직 상태(`hit`)를 유지하는 방식이다. 처음엔 1.5초였으나, 포효 동작(2.17초) 동안 시전자가 공격하지 못하므로 그만큼 늘려 3.7초로 했다. 기존 피격 경직과 같이 `staggerImmune` 몬스터와 스킬 시전 중인 몬스터에는 걸리지 않는다. 경직 중에는 이동·공격하지 않고, 공격 간격 타이머도 멈춘다. 막 공격한 몬스터에게 써도 다음 공격이 3.7초 늦어진다. 일반 피격 경직(0.8초)은 타이머를 멈추지 않는다.

포효를 맞은 몬스터는 시전자를 공격 대상으로 정하고, 시전자의 전투 시각을 갱신한다. 따라서 탈출할 때만 쓰는 스킬이 아니라 주변 몬스터를 끌어오는 위험이 있다.

임시 HP는 받은 피해를 먼저 흡수하고, 남은 양은 10초 뒤 사라진다. 최대 HP와 회복량을 바꾸지 않으며, 다시 받으면 큰 값으로 바꾸고 합산하지 않는다. HP 바 옆에 별도 색으로 표시한다.

| 기준 (CON 14) | 평균 최대 HP | 임시 HP |
| --- | ---: | ---: |
| 1레벨 | 14 | 4 |
| 30레벨 | 260 | 39 |
| 50레벨 | 430 | 64 |

### 구현 상태

- 서버: `AbilityId::PrimalRoar`. 임시 HP는 `Player.temp_health`(직렬화하지 않음)에, 지속 시간은 `Abilities.roars`에 둔다. 몬스터 피격과 디버프 피해가 `Player::absorb_damage`로 임시 HP를 먼저 깎는다. 임시 HP가 0이 되거나 10초가 지나거나 사망하면 버프가 끝난다. 본인에게만 `TempHealthUpdate`로 남은 양을 보낸다.
- 시점: 서버가 시전 직후 `player_attack_holds`에 1.85초 뒤 시각을 적어 그때까지 스윙을 막고(`hold_player_attack`, 전투 감사의 마지막 공격 시각은 건드리지 않는다), 1.05초 뒤 발 구르기 시점에 그때 시전자 위치로 몬스터를 찾는다. 그 사이 시전자가 죽으면 경직은 없다.
- 경직: 몬스터 두뇌의 `stagger_left_ms`가 경직 남은 시간을 센다. 경직 중 새로 맞아도 남은 시간은 줄지 않고 `max(남은 시간, 0.8초)`가 되며, 빗나간 공격은 경직을 풀지 않는다. 포효 경직은 그만큼 `attack_cooldown_left_ms`를 늘려 공격 간격을 멈춘다. 실제로 경직된 몬스터 목록은 `MonsterStunned`로 주변에 보낸다. 포효로 아무 몬스터도 맞지 않으면 전투 시각을 갱신하지 않는다. 투명 망토는 공격처럼 풀린다.
- 웹: Caveman **SKILLS**와 퀵슬롯, 버프 표시·툴팁, 5개 언어 문구. 임시 HP는 머리 위 HP 바에서 현재 HP 바로 뒤에 옅은 노란 칸으로 붙고(HP 바 길이는 그대로이며, 최대 HP를 넘는 부분은 바 오른쪽 밖으로 나간다), 캐릭터 창 HP 옆에 `+N`으로 보인다. 경직된 몬스터 머리 위에 노란 별 3개가 경직 동안 돈다. 피격 동작은 한 번 재생한 뒤 마지막 프레임에 멈춘다. 시전자는 Mixamo Roar 앞부분(웅크림 → 발 구르기 → 양팔을 벌린 포효 → 상체를 숙여 내지르기, 2.17초)을 idle·자동 공격 중에 한 번 재생하고, 0.8초 뒤 성별에 맞는 포효 소리가 같은 층 20m 안에 들린다. 이동 중에 쓰면 동작은 생략된다. 자동 공격 중에 쓰면 포효가 끝난 뒤 다음 공격이 실제로 나갈 때까지 전투 대기 자세를 유지하고, 공격 동작은 그 공격과 함께 처음부터 시작한다. 시전자 쪽 VFX는 없다.
- agent-client: `{"type":"use_ability","ability":"primal_roar"}`, Caveman 세계 상태에 준비·MP·임시 HP 안내.

## 4. 발할라의 돌격 (Valhalla Charge) — Valkyrie

| 항목 | 규칙 |
| --- | --- |
| ID | `valhalla_charge` |
| 분류 | 전투 기술, MP 1 |
| 장착 조건 | 주무기가 한손 Sword 또는 Spear. 보조 손 제한 없음 |
| 대상 | 살아 있는 몬스터 1마리. 마우스 아래 몬스터나 현재 대상에게 바로 쓴다. 둘 다 없으면 청진처럼 클릭 지정 모드가 되어, 다음에 왼쪽 클릭한 몬스터에게 돌격한다(Esc로 취소) |
| 사거리 | 같은 층, 4~10m(몸집이 있는 몬스터는 몸 표면까지). 시전자와 대상 사이 직선 경로가 이동 가능하고 벽이 없을 것 |
| 이동 | 시전자 무기의 근접 사거리 안에 들 때까지 0.4초에 직선 이동 |
| 공격 | 도착 즉시 기본 공격 1회. 명중·피해·치명타는 기본 공격과 같다 |
| 추가 효과 | 명중하면 대상의 이동 속도 ×0.6, 3초 |
| 재사용 | 10초. 몬스터 한 마리에 한 번 시작기로 쓰는 간격(Double Slash와 같음) |
| 공격 간격 | 기본 공격 간격이 끝나지 않았으면 거절한다. 돌진 공격은 기본 공격 1회로 계산해 다음 공격 간격을 시작한다 |

둔화는 몬스터 AI의 이동 속도(`move_speed`)에 배수로 적용한다. `boss` 몬스터와 `staggerImmune` 몬스터에도 걸리지만 지속시간은 1.5초로 줄인다. 다시 걸면 지속시간만 갱신한다.

돌진 이동은 서버가 결정한다. 서버는 시작 시 직선 경로를 검사하고 이동 큐를 비운 뒤 시전자를 도착 좌표로 바로 옮기고, 주변에 `PlayerCharged`로 출발·도착 좌표와 0.4초를 알린다. 클라이언트는 그동안 모델을 도착 좌표까지 달려가게 그린다. 돌진 중 대상이 사망하거나 사거리를 벗어나면 도착한 자리에서 멈추고 공격하지 않는다. 시작 후 취소돼도 재사용 대기는 유지한다(Double Slash와 같음).

### 구현 상태

- 서버: `AbilityId::ValhallaCharge`, [valhalla_charge.rs](../../server/src/game_state/valhalla_charge.rs). 거절 사유에 `TooClose`(4m 미만)·`Blocked`(직선 경로나 착지 지면 문제)를 추가했다. 기본 공격 간격이 남았으면 `Cooldown`으로 거절한다. 도착 지점은 대상 몸 표면에서 무기 사거리보다 0.3m 안쪽이다. 경로는 이동과 같은 폭 0.3m 스윕과 공격 선 검사로 확인하고, 던전 계단처럼 층이 바뀌는 착지는 거절한다.
- 동기화: 별도 이동 메시지 `PlayerCharged`를 쓴다. 서버 위치는 시전 즉시 도착 좌표가 되고, 기존 이동 요청 번호 체계와 이동 진단은 건드리지 않는다. 확인 응답은 없다. 0.4초 사이에 이동 요청이 오면(행동 버전이 바뀌면) 공격을 취소하고 거기서 이동을 시작한다.
- 공격: 시전 때 `dash + 기본 공격 간격` 동안 다른 스윙을 막는다. 0.4초 뒤 기본 공격과 같은 검사(`validate_player_attack`)를 다시 거쳐 기본 공격 1회를 치고, 그 시각부터 다음 공격 간격이 시작된다. 공격이 취소되면 막아 둔 스윙을 풀어 준다.
- 둔화: 몬스터 두뇌의 `slow_left_ms`·`slow_mult`가 이동 거리에 배수를 곱한다. 다시 걸면 지속시간만 갱신한다. `boss` 또는 `staggerImmune` 몬스터는 1.5초다. 주변에 `MonsterSlowed`를 보내 웹이 보간 속도를 같이 줄인다.
- 웹: Valkyrie **SKILLS**와 퀵슬롯, 툴팁, 5개 언어 문구. 대상이 없으면 클릭 지정 모드가 되며, 화면 아래 안내(5개 언어)와 조준 커서가 나온다. 지정 모드에서는 이동 중인 캐릭터를 멈추지 않는다. 돌진은 달리기 동작으로 0.4초 동안 가속하며 그리고(시작 속도는 평균의 0.5배, 끝은 1.5배), 그동안 클릭·드래그 이동을 받지 않는다. 도착 공격은 일반 공격의 휘두르기 지연(540ms)을 건너뛴다. 도착 0.3초 전부터 Rogue의 단검 찌르기(`dagger_stab`)를 손에 든 무기로 재생해 찌르는 순간이 도착과 겹치고, 몬스터 경직·타격음·피해 숫자도 도착 순간에 맞춘다. 서버는 도착 공격의 `PlayerAttacked`에 `charge`를 표시하고, 이 공격의 전리품도 Double Slash처럼 지연 없이 떨군다. 찌르기가 그 공격을 이미 보여 주므로 클라이언트는 이 확인으로 베기를 다시 하지 않는다. 찌르기 클립은 Valkyrie 모델에만 미리 불러 둔다. 도착할 때 시전자 화면이 돌진 방향으로 짧게 흔들린다(투영만 밀어서 카메라 거리는 바뀌지 않는다). 시전 직후 그 몬스터에 자동 공격을 걸어, 도착 공격 뒤 평소처럼 이어서 싸운다. 응답을 기다리는 동안에는 추격 경로를 새로 보내지 않는다(새 이동 요청이 도착 공격을 취소하기 때문). 아이콘은 날개 달린 창이 앞으로 찌르는 모양이다([`valhalla-charge.png`](../../client/public/icons/skills/valhalla-charge.png), [생성 프롬프트](../assets/valhalla-charge-icon-prompt.txt)). 전용 동작·효과음·VFX는 없다.
- agent-client: `{"type":"use_ability","ability":"valhalla_charge","target":"m21"}`, Valkyrie 세계 상태에 준비·MP·사거리 안내, `PlayerCharged`로 자기 위치를 갱신한다.

| 항목 | 규칙 |

| ID | `healing_prayer` |
| 분류 | 치유 마법 |
| 비용 | MP 6 |
| 장착 조건 | 없음 |
| 대상 | 자신, 살아 있는 플레이어 1명(파티 여부 무관), 또는 살아 있는 언데드 몬스터 1마리 |
| 사거리 | 같은 층, 10m, 시야 확보 |
| 효과 | 플레이어: HP `max(1, 2d6 + floor(Level / 3) + wis_mod)` 회복. 최대 HP 초과분은 버린다<br>언데드: 같은 굴림만큼 피해 |

`wis_mod = trunc((WIS - 10) / 2)`로 MP 계산과 같다. 대상 HP가 가득 찼으면 거절하고 MP를 쓰지 않는다. 대상이 전투 중이면 시전자의 전투 시각도 갱신한다. 전투 중인 동료를 치유하면서 MP 자연 회복을 받는 일을 막기 위해서다.

| 기준 (WIS 17, +3) | 1회 평균 회복 | 최대 MP | MP 바 전체로 회복 | 초당 회복 (연속 시전) |
| --- | ---: | ---: | ---: | ---: |
| 1레벨 | 10 | 18 | 3회, 30 | 1.25 |
| 30레벨 | 20 | 137 | 22회, 440 | 2.5 |
| 50레벨 | 26 | 220 | 36회, 936 | 3.25 |

전투 중에는 MP가 회복되지 않으므로 MP 바 하나가 한 전투의 치유 예산이다. 50레벨 936 HP는 큰 회복 물약(`12d4`, 평균 30, 1,500골드) 31개, 약 47,000골드어치다. 파티에 Priest가 있으면 물약 소비가 줄어든다. 이 영향은 8절에서 확인한다.

### HP 공개 범위

다른 플레이어의 정확한 HP는 기본으로 공개하지 않는다. 나중에 PvP가 생기면 상대 HP를 모르는 것이 재미 요소이기 때문이다.

지금은 서버가 주변 모든 클라이언트에 플레이어 정보(`health`·`max_health`)와 `PlayerHealthUpdate`를 보낸다. 웹은 본인 HP 바와 파티 창에만 HP를 표시하고, 다른 플레이어의 HP는 시체 표시·마우스 올림 같은 생존 판정에만 쓴다. agent-client는 주변 플레이어의 HP를 LLM 프롬프트에 넣는다. 사람은 못 보고 에이전트는 보는 상태다.

| 받는 쪽 | 받는 정보 |
| --- | --- |
| 주변 플레이어 | 생존 여부만 |
| 본인 | 정확한 HP·최대 HP |
| 파티원 | 정확한 HP·최대 HP (기존 `PartyVitals`) |
| 청진기 착용자 | 주변 정보를 받는 범위(`EVENT_DELIVERY_RADIUS`, 현재 32m) 안 플레이어의 정확한 HP·최대 HP |

- 사람과 에이전트가 같은 정보를 받는다. agent-client의 주변 플레이어 HP 표시도 이 범위를 따른다.
- Priest는 파티원을 파티 창으로 보고 치유한다. 파티 밖 플레이어도 치유할 수 있지만 HP는 모른다. [청진](AUSCULTATION.md)으로 한 번 확인하거나 청진기를 착용해 계속 본다.
- 청진기 착용자의 HP 표시는 장착 효과이며 MP를 쓰지 않는다. 별도 범위 검사 없이 기존 주변 정보(플레이어 정보·HP 변경)와 같은 범위로 보낸다. 서버는 변경 메시지를 한 번 인코딩해 받는 사람 모두에게 재사용하므로, HP를 넣은 판과 뺀 판 두 가지를 만들어 착용자에게만 HP 판을 보낸다. 변경당 인코딩이 최대 두 번으로 늘 뿐이다.
- "대상 HP가 가득 찼으면 거절" 규칙은 가득 찼는지를 알려 준다. PvP가 생기면 적대 대상은 치유 대상에서 뺀다.
- 공개 범위 변경은 프로토콜 변경이다. 치유의 기도와 같은 v133에 묶었다.
- 구현: 별도 생존 여부 필드를 두지 않았다. HP를 받지 못하는 사람에게는 `health`를 생존 시 1, 사망 시 0으로, `max_health`를 0으로 보낸다. 기존 `health > 0` 생존 판정이 그대로 맞고, `max_health == 0`이 "HP 모름"이다. 대상은 `Player`(`PlayerJoined`·`PlayerAppeared`·`PlayerRespawned`), `PlayerHealthUpdate`, `MonsterAttackedPlayer.current_health`, `MonsterSkillStruck` 피격자의 `current_health`다. `XpGained`·`JoinSuccess`는 본인에게만 간다.
- 서버는 주변 전송(`Interest`)에서 가린다. 구독 갱신은 플레이어 주체마다 "HP 보임/가림" 두 판만 인코딩하고, 시야 진입 스냅샷은 받는 사람마다 이미 따로 인코딩하므로 거기서 가린다. 주변 효과(`publish_effect`)는 피격자 본인 판과 가린 판을 따로 인코딩한다. 청진기 착용자 목록은 게임 입장과 장비 변경(`set_player_gear`) 때 갱신하고, 바뀌면 보이는 플레이어의 HP를 다시 보낸다. 캐릭터가 게임에서 빠질 때(`remove_player`) 지운다.

### 언데드 대상

`monsters.csv`에 `undead` 열을 추가하고 해골 계열 네 종에 `true`를 넣는다.

| ID | 이름 | 레벨 | Guard | HP |
| --- | --- | ---: | ---: | ---: |
| `skeleton_weak` | Forgotten Dead | 8 | 14 | 40 |
| `skeleton` | Skeleton | 16 | 20 | 72 |
| `skeleton_warrior` | Skeleton Warrior | 20 | 24 | 90 |
| `skeleton_knight` | Skeleton Knight (보스) | 25 | 32 | 350 |

언데드가 아닌 몬스터를 지정하면 거절하고 MP를 쓰지 않는다. 언데드 피해는 명중 판정 없이 들어가며 치명타·INT·무기 보정을 받지 않는다. 마법 Guard가 정해지지 않은 지금은 판정할 기준이 없기 때문이며, 몬스터 마법 Guard가 생기면 다시 검토한다. 공격이므로 대상은 시전자를 표적으로 삼고 시전자의 전투 시각을 갱신한다.

해골은 Guard가 높아 Priest의 근접 공격이 잘 맞지 않는다. 20레벨 Priest(STR 9, `morningstar` 1d8)가 Skeleton Warrior(Guard 24)를 때리면 명중률 25%, 초당 기대 피해 약 0.6이다. 치유의 기도는 1회 평균 16, 초당 2로 약 3.5배다. 대신 MP 6씩 들어 20레벨 MP 96으로 16회, 약 256 피해에서 끝난다. Skeleton Warrior는 6회, Skeleton Knight(HP 350)는 MP 바 하나로 잡을 수 없다.

### 구현 상태

- 서버: `AbilityId::HealingPrayer`, [healing_prayer.rs](../../server/src/game_state/healing_prayer.rs). 거절 사유에 `FullHealth`(HP 가득)·`NotUndead`(언데드 아님)를 추가했다. 시야가 막히면 `Blocked`, 10m 밖이면 `OutOfRange`다. 대상 없이 쓰면 자신을 치유한다. 앉거나 누운 대상은 청진과 같이 그 가구를 뺀 통행 정보로 시야를 본다. 언데드 피해는 기본 공격과 같은 몬스터 피해·처치 경로(`damage_monster`)를 써서 피해 비율 경험치 분배·전리품·사망 처리가 같다. 언데드에게 쓰면 투명 망토가 공격처럼 풀린다. 투명한 채 플레이어를 치유하면 `HealingPrayed`는 시전자에게만 간다. 성공하면 주변에 `HealingPrayed`(시전자, 대상, 회복량 또는 피해)를 보내고, HP 변화는 기존 `PlayerHealthUpdate`·`PartyVitals`로 따로 간다.
- 데이터: `monsters.csv` `undead` 열. `skeleton_weak`·`skeleton`·`skeleton_warrior`·`skeleton_knight`가 `true`다.
- 웹: Priest **SKILLS**와 퀵슬롯, 툴팁, 5개 언어 문구. 대상은 마우스 아래에서 고른다. 파티 창의 파티원 줄 → 다른 플레이어 → 언데드 몬스터 순이고, 아무것도 없거나 언데드가 아닌 몬스터 위면 자신이다. 전투 대상으로 잡아 둔 몬스터는 쓰지 않는다. 해골과 싸우다 자신을 치유하려는 경우가 더 많아서다. HP를 아는 대상(자신, 파티원, 청진기로 보이는 플레이어)이 가득 찼으면 보내지 않고 바로 실패 안내를 띄운다. 언데드는 무기 소리·화살 없이 바로 움찔하고 시전자에게 피해 숫자가 뜬다. 회복은 시전자와 대상의 전투 로그에 나오고, 자신이 회복되면 기존 초록 회복 숫자가 뜬다. 다른 플레이어가 회복되면 `HealingPrayed`를 받은 주변 클라이언트에서 그 머리 위에 같은 초록 `+회복량`이 뜬다. HP가 숨겨진 대상도 HP 차이가 아니라 `amount`로 띄운다. 청진기 착용자에게는 다른 플레이어 머리 위에 HP 바가 보인다. 아이콘은 원래 Radiance용으로 만든 빛 문양을 옮겨 왔다([`healing-prayer.png`](../../client/public/icons/skills/healing-prayer.png)). 숨겨 둔 Radiance는 새 아이콘을 그릴 때까지 같은 파일을 쓴다. 시전자는 Mixamo Magic Heal(한 손을 앞으로 뻗는 2.7초 동작, `heal`)을 idle·자동 공격 중에 한 번 재생한다. 서버가 시전 중 스윙을 막지 않으므로 다음 자동 공격 스윙이 오면 동작이 끊긴다. 이동 중에는 생략된다. 효과음 [`healing-prayer.ogg`](../../client/public/sounds/healing-prayer.ogg)는 `HealingPrayed`마다 한 번, 시전자 20m 안에서 볼륨 0.25로 재생한다(가디언 와드보다 약 5dB 작다). VFX는 없다.
- agent-client: `{"type":"use_ability","ability":"healing_prayer"}`(자신), `"target"`에 플레이어 이름 또는 언데드 몬스터 ID. Priest 세계 상태에 준비·MP·사거리·예상 회복량·언데드 목록을 안내한다. 다른 플레이어 HP는 `max_health > 0`일 때만 수치로, 아니면 생존 여부만 보여 준다. 파티원 HP는 `PartyVitals`로 정확히 유지한다.

## 6. 전투의 찬가 (Battle Hymn) — Bard

| 항목 | 규칙 |
| --- | --- |
| ID | `battle_hymn` |
| 분류 | 지원 마법 |
| 비용 | MP 5. 연주가 끝날 때 쓴다 |
| 장착 조건 | `instrument` 아이템 소지. 가방에 있어도 된다(연주 규칙과 같음) |
| 시전 | 10초 동안 찬가 행진곡(녹음 3곡 중 무작위 하나)을 연주한다. 라이브 연주나 `/play_music` 중이었으면 그 곡을 멈추고 찬가로 바꾼다. 끝나면 연주 자세가 풀린다 |
| 대상 | 연주가 끝날 때 같은 층 20m 안의 살아 있는 자신과 파티원 |
| 효과 | 이동 속도 ×1.08, 공격 속도 ×1.08, 10분 |
| 재사용 | 없음. 연주 중 다시 쓰면 거절한다 |

10초 안에 이동·공격·피격·순간이동·연주 종료(Esc, 거래 등)나 다른 곡 연주(`/play_music`, 라이브 연주)가 생기면 중단되고 연주 자세와 멜로디도 멈춘다. 중단되면 MP를 쓰지 않고 곧바로 다시 시작할 수 있다. 연주가 끝나는 순간 MP가 5보다 적으면 효과 없이 끝난다.

범위는 연주가 끝나는 순간에만 본다. 효과를 받은 뒤에는 멀리 가도, 파티를 나가도 10분간 유지된다(Guardian Ward와 같음). 사망·로그아웃 때 해제된다. 다시 받으면 남은 시간이 10분으로 갱신되고, 여러 Bard의 찬가는 중첩되지 않는다. 이동 배수는 말·배 속도에도 곱해진다.

### 손익

처음에는 연주하는 동안에만 유지하고 5초마다 MP 1을 쓰는 방식이었다. Bard는 연주 중에 공격하지 못하므로 그 피해만큼 파티가 손해를 본다. 50레벨에서는 무기 주사위와 강화가 STR 보정보다 커서, STR −2인 Bard도 전사 피해의 70~80%를 낸다. 반면 +8%는 파티원 4명을 합쳐도 전사 1명 피해의 32%다.

파티 전체 피해 변화(Bard STR 8, 치명타 포함 모의 계산):

| 방식 | 파티원 1명 | 2명 | 4명 |
| --- | ---: | ---: | ---: |
| 연주 중에만 유지, 50레벨 vs Skeleton Warrior | −36% | −20% | −8% |
| 10초 연주 후 10분, Bard 포함 | +7% | +8% | +8% |

10분 방식은 Bard가 10분 중 10초만 공격을 쉬고, 전투 사이에 연주하면 손실이 없다. 전사 1명 피해를 1로 두면 늘어나는 피해는 혼자 +0.06, 2인 +0.14, 3인 +0.22, 5인 +0.38이다. 혼자일 때는 연속 베기(+0.12)·광폭화(+0.20~0.24)보다 작고, 3인에서 광폭화와 비슷하며, 5인이면 그보다 크다. 파티가 클수록 커지는 점은 Guardian Ward(파티 Guard +2 + Level/20, 45초마다 다시 걸어 계속 유지)와 같다. MP 소모는 분당 0.5로 Guardian Ward(2.7)·광폭화(3)보다 훨씬 적어, 연주 10초가 실제 대가다.

### 구현 상태

- 서버: `AbilityId::BattleHymn`, [battle_hymn.rs](../../server/src/game_state/battle_hymn.rs). 연주 중인 Bard는 `Abilities.hymns`에 둔다. 연주 중인 동안은 그 남은 시간을 스킬 재사용 대기로 보고하므로, 다시 쓰면 `Cooldown`으로 거절되고 퀵슬롯에 남은 시간이 보인다. 시작할 때 연주 자세(`MUSIC_EMOTE`)를 잡고(이미 연주 중이면 `/play_music` 기록과 라이브 연주를 지운다) 주변에 `BattleHymnStarted`(시전자, 위치, 층, 곡 번호)를 보낸다. 곡은 서버가 무작위로 골라 모두가 같은 곡을 듣는다. 거절 사유는 Bard가 아니거나 죽었거나 탑승 중이면 `Unavailable`, 악기가 없으면 `Equipment`, MP 5 미만이면 `NotEnoughMana`다. 중단은 새 사유 `Interrupted`로 알린다.
- 완료: 250ms 배고픔 틱(`tick_battle_hymns`)이 10초가 된 Bard를 찾는다. 그때 연주 자세·생존·악기를 다시 확인하고 연주 자세를 푼 뒤, MP 5를 쓰고 효과를 걸고 주변에 `AbilityUsed`(대상 목록 포함)를 보낸다.
- 중단: 연주 자세에서 벗어나면(`set_player_interaction`), 연주 중 순간이동(`apply_player_position`), 연주 중 몬스터 공격 명중(`land_monster_hit`, 이때는 연주 자세도 푼다), `/play_music`·라이브 연주 시작 때 즉시. 모두 연주 자세일 때만 확인하므로 다른 이동·피격에는 비용이 없다. 사망·로그아웃은 `clear_buffs`가 지운다.
- 효과: 받는 사람의 `HungerData.hymn_until`에 둔다. `debuff_mults`가 이동·공격 배수에 1.08을 곱하므로 이동 속도, 공격 간격, `HungerUpdate`, 공격 예약 재계산(`next_attack_mult_change`)이 디버프와 같은 경로를 탄다. 만료는 `tick_debuffs`, 사망 해제는 `clear_debuffs`가 처리한다. 운영 NPC는 배고픔 항목이 없어 받지 않는다. 버프 목록에는 `BuffUpdate`의 `battle_hymn`으로 남은 시간과 함께 나간다.
- 웹: Bard **SKILLS**와 퀵슬롯, 툴팁, 5개 언어 문구. 악기는 가방에 있어도 된다(`abilityEquipmentAllowed`가 가방을 본다). 버프 배지는 10분부터 줄어든다. 효과 중인 이동·공격 배수는 상태 창의 이동·공격 수치에도 반영된다. 아이콘은 다른 스킬과 같은 흑백 붓선 스타일의 만돌린과 음표다([`battle-hymn.png`](../../client/public/icons/skills/battle-hymn.png), [생성 프롬프트](../assets/battle-hymn-icon-prompt.txt)). `BattleHymnStarted`를 받으면 그 Bard의 곡과 라이브 연주 음을 멈추고, 고른 행진곡(`client/public/sounds/battle-hymn-1~3.ogg`, Eleven Music으로 생성한 10초 녹음)을 Bard 위치에서 라이브 연주와 같은 거리 감쇠로 재생한다(기본 음량 0.45). Bard 본인도 듣고 연주 동작에 들어간다. 효과음 음량을 따르므로 BGM을 꺼도 들리며, 재생 중에는 라이브 연주처럼 BGM을 낮춘다. 연주 자세가 풀리면 곡을 멈춘다. 전용 동작·VFX는 없다.
- agent-client: `{"type":"use_ability","ability":"battle_hymn"}`. Bard 세계 상태에 준비·연주 남은 시간·MP·범위 안내, 효과를 받는 캐릭터에게 남은 시간 한 줄. 완료와 중단을 이벤트로 알린다.
